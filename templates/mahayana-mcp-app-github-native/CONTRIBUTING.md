# Contributing

Open or link an Issue before public work. Work in a fork and a dedicated branch. Do not commit tokens, cookies, credentials, private logs, user data, generated build output, or local package caches.

A Pull Request must include:

- issue link and reproduction
- root cause and change summary
- tests executed
- permission differences
- Tool Contract differences
- artifact and platform impact
- AI assistance disclosure when applicable

Fork pull requests are untrusted. They cannot receive secrets, write upstream, create official release assets, or publish. Maintainers decide when an approved change is released.
