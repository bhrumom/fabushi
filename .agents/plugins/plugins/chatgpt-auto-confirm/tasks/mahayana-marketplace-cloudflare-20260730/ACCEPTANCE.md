# 验收标准：大乘小程序混合市场与可信发布

任务只有在本文件所有“必须”项均满足，并给出可复核云端证据后才能报告 `complete`。

## 1. 代码和迁移

- [ ] 现有官方内置市场、公共 `.well-known` 清单和已安装官方插件没有被破坏。
- [ ] 动态市场具备清晰的 v2 协议或等价向后兼容扩展。
- [ ] 数据库迁移可重复执行，旧数据可读取，新字段和新表有契约测试。
- [ ] 旧固定 `/mahayana/plugin.tar.gz` 只作为 legacy 兼容来源，新正式版本必须使用不可变路径。
- [ ] 新旧客户端兼容策略有自动测试。

## 2. 插件身份和隔离

- [ ] 一个发布者账号可以拥有多个插件。
- [ ] 完整 plugin ID 采用稳定命名空间，发布后不能被其他账号占用。
- [ ] 不同发布者不能覆盖或接管别人的 plugin ID。
- [ ] 同一 `pluginId + version` 永远不能再次发布，即使旧版本被撤销。
- [ ] 每个测试插件拥有独立 Cloudflare Worker/Pages 项目或服务边界。
- [ ] 插件之间不共享写 Secret、数据库、部署凭证或写权限。
- [ ] 没有为每个版本永久创建新的 Worker 项目名称。

## 3. 不可变部署和回滚

- [ ] 示例插件至少发布 `1.0.0` 和 `1.1.0` 两个版本。
- [ ] 两个版本均使用 `/mahayana/releases/<version>/<sha256>/...` 或等价不可变路径。
- [ ] URL 中的哈希与实际安装包 SHA-256 一致。
- [ ] 重新获取已发布 URL 得到完全相同的内容、大小和哈希。
- [ ] `latest` 仅作为指针，正式安装包不使用可覆盖地址。
- [ ] production deployment/alias 能从 `1.0.0` 提升到 `1.1.0`。
- [ ] 能把 production deployment 回滚到 `1.0.0`，且没有重新上传或修改旧版本。
- [ ] 旧版本在回滚保留期内仍可获取。
- [ ] 插件包和静态资源均未使用 R2。

## 4. 托管发布体验

- [ ] 普通测试发布者只使用大乘账号和 CLI，不输入 Cloudflare Token。
- [ ] `mahayana plugin init` 或等价能力能生成插件身份和契约文件。
- [ ] `mahayana plugin test` 或等价能力能执行 manifest、权限、包边界、安装和启动检查。
- [ ] `publish --stage` 创建预览部署和待审核版本，不直接误报公开成功。
- [ ] `release` 完成正式不可变部署、签名、provenance 和审核提交。
- [ ] 发布阶段和错误对普通用户可理解。
- [ ] 日志和 CLI 输出没有泄露 Cloudflare、市场或 OIDC 凭证。

## 5. OIDC 和来源证明

- [ ] GitHub Actions 通过 OIDC 获取短期发布凭证。
- [ ] 凭证限制到发布者、plugin ID、仓库、workflow、commit、权限和有效期。
- [ ] 错误仓库、错误 workflow、错误 plugin ID、过期 token 和重放 nonce 均被拒绝。
- [ ] 正式发布不依赖长期测试账号或长期市场写 Token。
- [ ] provenance 记录源码仓库、commit SHA、workflow、Actions run、构建者、构件 SHA 和部署地址。
- [ ] 市场和 CLI 能展示或查询 provenance。
- [ ] provenance 与实际 Actions run 和 commit 可互相核对。

## 6. 市场签名和更新安全

- [ ] 市场对规范化版本元数据签名。
- [ ] CLI 使用受信任公钥验证签名。
- [ ] 篡改 plugin ID、version、URL、SHA、大小、权限、状态或过期时间会导致签名失败。
- [ ] 元数据包含版本号和过期时间。
- [ ] CLI 拒绝过期、旧版本冻结、混搭或低于最高已知安全版本的元数据。
- [ ] 有可验证的密钥 ID、轮换和撤销结构。
- [ ] 撤销列表或签名状态能阻止被撤销版本的新安装和升级。

## 7. 权限

- [ ] 示例插件声明网络、文件系统、Secret、命令、MCP tools 和 UI surface 权限。
- [ ] 市场元数据和包内 manifest 的权限必须一致。
- [ ] 未声明权限默认拒绝。
- [ ] 首次安装显示完整权限。
- [ ] `1.1.0` 至少引入一个可控的权限变化，用于验证权限 diff。
- [ ] 权限扩大不能静默升级，必须重新确认。
- [ ] 用户拒绝权限后，旧版本仍可正常运行且不留下半升级状态。

## 8. 市场审核等级和生命周期

- [ ] 支持 `private`、`unlisted`、`community`、`verified`、`official`、`blocked`。
- [ ] 普通发布者首次提交默认为 `unlisted + pending`。
- [ ] 未批准版本不会出现在公开搜索结果中。
- [ ] approved/community 版本可被发现和安装。
- [ ] verified/official 等级有明确授予条件和审计记录。
- [ ] blocked 插件不能新安装或升级。
- [ ] 单版本 revoke 与插件整体 blocked 可以区分。
- [ ] 安全状态变化能被 CLI 和 UI 读取。

## 9. 直连下载和安全安装

- [ ] 市场返回插件 Cloudflare 不可变直接下载 URL。
- [ ] 市场 Worker 没有永久代理安装包字节；兼容端点最多返回元数据或重定向。
- [ ] CLI 只接受批准的 Cloudflare HTTPS 域名和无凭证 URL。
- [ ] CLI 验证 Content-Length/流式最大大小、内容类型、大小和 SHA-256。
- [ ] CLI 验证市场签名、provenance、权限、版本和撤销状态。
- [ ] 安全解包拒绝绝对路径、`..`、链接逃逸、文件数量炸弹和超大解压。
- [ ] 安装使用隔离临时目录和原子切换。
- [ ] 下载或启动失败不破坏当前已安装版本。
- [ ] 重复安装和重试具有幂等结果。

## 10. 自托管模式

- [ ] 高级发布者可以登记自己的 Cloudflare 服务。
- [ ] 市场验证部署或域名所有权。
- [ ] 非 Cloudflare、HTTP、本地地址、带用户名密码或异常重定向的 URL 被拒绝。
- [ ] 自托管版本也必须使用不可变路径、签名市场元数据、权限、审核和撤销机制。
- [ ] 自托管不能绕过包大小、SHA、provenance 和安装安全检查。

## 11. 真实示例插件端到端

必须创建一个真实第三方示例插件，例如：

```text
io.mahayana.test.hello
```

不得复用仅内置的官方插件作为唯一证据。必须完成：

1. 通过普通测试账号登录；
2. 初始化插件；
3. 本地/Actions 契约测试；
4. stage 发布；
5. Cloudflare 预览部署；
6. 正式 release；
7. 待审核状态；
8. 审核批准；
9. 市场搜索和详情；
10. CLI 获取签名元数据；
11. 直连 Cloudflare 下载；
12. 完整校验；
13. 安装和运行；
14. 发布第二版本；
15. 权限扩大确认；
16. 升级并运行；
17. 回滚到第一版本；
18. 撤销第一版本；
19. 拒绝重新安装被撤销版本；
20. 篡改包、哈希、元数据或来源时拒绝安装。

## 12. 失败场景

至少自动覆盖：

- [ ] plugin ID 被其他发布者占用；
- [ ] 重复版本；
- [ ] OIDC claims 不匹配；
- [ ] 发布 nonce 重放；
- [ ] 非批准域名；
- [ ] 可变或错误版本路径；
- [ ] 大小不一致；
- [ ] SHA-256 不一致；
- [ ] 签名无效；
- [ ] provenance 不匹配；
- [ ] 权限不一致；
- [ ] 路径穿越或链接逃逸；
- [ ] 网络中断；
- [ ] 启动健康检查失败；
- [ ] 版本回退；
- [ ] 过期或冻结元数据；
- [ ] revoked/blocked 状态。

## 13. GitHub Actions 验证

- [ ] 所有新增单元、契约、迁移和安全测试通过。
- [ ] 至少一个 Actions workflow 完成真实 Cloudflare stage 和 release。
- [ ] 至少一个干净环境完成 CLI 浏览、安装、启动、升级和回滚。
- [ ] Actions 产物和日志保留 plugin ID、版本、SHA、部署 URL、run ID 和结果摘要。
- [ ] 不在本地电脑运行项目构建、发布或重型测试作为最终证据。

## 14. 最终机器报告

最终报告 `verification` 必须逐项给出：

- PR 与合并提交；
- 数据库迁移；
- GitHub Actions run；
- OIDC 交换证据；
- Cloudflare 项目、版本和生产部署；
- 示例 plugin ID 和两个版本；
- 不可变安装包 URL、SHA 和大小；
- 市场签名与 provenance；
- 审核和信任等级；
- CLI 直连下载、安装、运行、升级、回滚；
- 撤销和篡改拒绝；
- 无 R2、无永久市场代理、无长期普通发布 Token 的证据。

缺少任一强制证据时，状态必须为 `incomplete`，并在 `next_task` 中列出准确续作。
