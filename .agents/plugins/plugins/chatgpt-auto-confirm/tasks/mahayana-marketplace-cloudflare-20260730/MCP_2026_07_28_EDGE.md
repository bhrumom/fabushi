# MCP 2026-07-28：大乘小程序边缘运行升级设计

## 文档地位

本文件是任务 `mahayana-marketplace-cloudflare-20260730` 的强制实施依据。

目标是把大乘现有的小程序 MCP 宿主、插件 MCP 服务和 Cloudflare 边缘部署升级到 MCP `2026-07-28`，同时保留旧协议兼容迁移能力。不得只修改版本字符串；必须完成协议、宿主、服务端、MCP Apps、长任务、授权、缓存、追踪和真实边缘部署的系统性迁移。

## 已确认的最新升级

MCP `2026-07-28` 已于 2026 年 7 月 28 日正式发布，是 MCP 自发布以来最大的一次协议升级。与大乘最相关的变化包括：

- 协议核心改为无状态；
- 移除强制 `initialize` / `notifications/initialized` 握手；
- 移除协议级 `Mcp-Session-Id`；
- 新增必须实现的 `server/discover`；
- 每个请求携带协议版本、客户端信息和能力元数据；
- HTTP 请求使用 `Mcp-Method`、`Mcp-Name` 等标准头，便于边缘路由、限流和观测；
- 使用 Multi Round-Trip Requests（MRTR）处理 elicitation 等服务端向客户端索取输入的场景；
- `tools/list`、资源读取等结果支持 `ttlMs` 和 `cacheScope`；
- 标准化 W3C Trace Context / OpenTelemetry 传播；
- MCP Apps 成为正式扩展；
- Tasks 成为独立正式扩展；
- Tool 输入和输出支持完整 JSON Schema 2020-12；
- OAuth / OpenID Connect 授权要求加强；
- Roots、Sampling、Logging 进入弃用阶段。

Cloudflare Agents SDK `v0.20.0` 已增加 MCP `2026-07-28` 客户端和服务端支持。新的 `createMcpHandler()` 可以在 Workers 上运行无状态 MCP 服务，并对旧客户端提供兼容路径；普通 tools、prompts、resources 和 elicitation 不再要求 MCP transport session 或 Durable Object。

## 当前大乘实现的差距

当前仓库的小程序宿主仍有以下旧协议行为：

- `MiniAppRegistry.hostApiVersion` 默认固定为 `mcp-2025-06-18`；
- Web MCP 客户端显式调用 `initialize`；
- 随后发送 `notifications/initialized`；
- 保存并重复发送 `Mcp-Session-Id`；
- 通过长期 `GET` / SSE 监听服务端通知；
- 通过 `DELETE` 终止协议会话；
- 客户端能力仍声明 `roots`；
- 小程序 iframe 通信是大乘自定义 MCP Apps 风格桥接，尚未完整采用官方 MCP Apps AppBridge、`ui://` 资源、CSP 和能力协商。

这些行为虽然可用，但会让边缘部署依赖会话粘性、共享状态或长期连接，也使大乘小程序难以直接兼容其他 MCP Apps 宿主。

## 目标架构

```text
大乘 App / Web / CLI MCP Host
        │
        ├─ server/discover 自动探测
        │     ├─ MCP 2026-07-28 无状态路径
        │     └─ 旧 initialize 路径（迁移期回退）
        │
        ▼
插件独立 Cloudflare Worker / Pages Functions
        │
        ├─ createMcpHandler（无状态 MCP）
        ├─ Tools / Prompts / Resources
        ├─ MCP Apps ui:// 资源
        ├─ Tasks 扩展
        ├─ OAuth/OIDC 权限
        └─ 显式业务状态句柄
              ├─ D1 / KV / Durable Object（仅业务确实需要时）
              ├─ Queue / Workflow（长任务）
              └─ 不作为 MCP transport session
```

核心原则：

> MCP 传输层无状态，应用业务可以有状态；业务状态必须通过显式 ID、task handle、resource URI 或授权主体表达，不能继续隐藏在协议会话中。

## 一、无状态边缘 MCP 服务

### 服务端

每个新插件的 Cloudflare 服务默认使用：

```text
agents/mcp/server createMcpHandler
+ MCP SDK v2 server factory
+ MCP 2026-07-28 stateless transport
```

普通工具请求必须满足：

- 任意边缘实例都能独立处理；
- 不创建 `Mcp-Session-Id`；
- 不依赖 sticky session；
- 不依赖 transport session 对象；
- 不要求长期 SSE 连接；
- 请求中的 `_meta` 足以解释协议版本、客户端和能力；
- 业务连续性通过显式参数传递，例如 `workspaceId`、`draftId`、`deploymentId`、`taskId`。

只有确实需要并发协调、强一致状态或 WebSocket 生命周期时才能使用 Durable Object，而且它必须是插件业务资源，不得重新包装成 MCP transport session。

### 客户端

大乘宿主必须实现协议自动协商：

1. 优先调用 `server/discover`；
2. 服务支持 `2026-07-28` 时进入无状态路径；
3. 不支持或返回明确兼容信号时，回退到旧 `initialize` 路径；
4. 协商结果按服务器身份和元数据有效期缓存；
5. 不允许因为一次瞬时网络错误永久降级；
6. 市场元数据声明服务器最低、最高和推荐协议版本。

迁移期必须双向兼容：

- 新大乘宿主连接新服务；
- 新大乘宿主连接旧服务；
- 旧大乘客户端连接提供 legacy compatibility 的新服务。

## 二、边缘路由、缓存和观测

### 标准 HTTP 头

Cloudflare 网关必须读取并校验：

- `MCP-Protocol-Version`；
- `Mcp-Method`；
- `Mcp-Name`；
- 认证主体；
- 插件 ID 和版本路由上下文。

可基于这些字段实现：

- 每个插件、发布者、用户、工具的限流；
- 只读工具与写工具不同配额；
- 高风险工具单独 WAF / 审核策略；
- 按方法和工具名统计延迟、错误率和调用量；
- 不解析 JSON body 即完成初步路由和安全策略；
- 请求头与 body 方法不一致时拒绝请求。

### MCP 缓存语义

`tools/list`、`prompts/list`、资源模板和 UI 资源应返回合理的：

- `ttlMs`；
- `cacheScope`。

建议：

- 插件公开工具清单：可使用插件版本级共享缓存；
- 与用户权限有关的工具清单：只能私有缓存；
- 不可变 `ui://` 资源：按插件版本和内容哈希长期缓存；
- 当前生产别名或权限状态：短 TTL；
- 撤销、安全公告和权限变更：不得被长时间缓存。

### 分布式追踪

宿主、市场 API、插件 Worker、Tasks 后端及下游 API 必须传播 W3C Trace Context。验收证据应能把一次用户操作关联为同一 trace：

```text
大乘宿主
→ 市场元数据
→ 插件 Worker
→ tool call
→ task / downstream service
→ 返回结果
```

日志不得依赖已弃用的 MCP Logging 作为唯一观测方式；结构化观测使用 OpenTelemetry，stdio 本地插件使用 stderr。

## 三、官方 MCP Apps 替代自定义 UI 方言

大乘小程序应正式实现 MCP Apps，而不是继续维护仅大乘可用的 iframe 协议。

### 插件服务声明

UI 工具必须：

- 在 tool `_meta.ui.resourceUri` 中声明 `ui://` 资源；
- 将 HTML、JS、CSS 作为 MCP UI resource 提供；
- 声明 CSP 允许的外部域名；
- 声明需要的浏览器权限；
- 声明工具对 model、app 或二者的可见性；
- 同时返回适合模型的 `content` 和适合 UI 的 `structuredContent`。

### 大乘宿主

Web、桌面和移动宿主应使用官方 AppBridge 或与规范一致的实现完成：

- sandboxed iframe；
- `ui/initialize`；
- host context：主题、locale、timezone、平台、尺寸；
- `ui/notifications/tool-input`；
- `ui/notifications/tool-result`；
- app 发起 `tools/call`；
- `ui/message`；
- `ui/update-model-context`；
- `ui/open-link`；
- `ui/resource-teardown`；
- inline、fullscreen、picture-in-picture 能力协商；
- CSP、权限和工具调用同意审计。

### 渐进增强

MCP Apps 只能是增强能力，不能成为工具可用性的硬依赖：

- 支持 MCP Apps 的宿主显示交互界面；
- 不支持 MCP Apps 的宿主仍能以文本和结构化结果使用工具；
- 同一插件不得维护互不兼容的“大乘专用工具”和“标准 MCP 工具”。

这样，大乘市场发布的小程序可同时服务：

- 大乘 App；
- 大乘 CLI；
- ChatGPT 等支持 MCP Apps 的宿主；
- Claude、VS Code、Microsoft 365 Copilot 等兼容宿主；
- 纯 MCP 客户端的文本降级模式。

## 四、MRTR 与用户确认

当前依赖服务端主动推送和长期 SSE 的 elicitation 流程，迁移为 MRTR：

1. 用户或 Agent 发起 `tools/call`；
2. 服务端需要用户输入或确认时返回 `input_required`；
3. 结果包含 `inputRequests` 和不透明 `requestState`；
4. 大乘宿主显示表单、URL 授权或高风险确认；
5. 宿主将 `inputResponses` 与原 `requestState` 重新提交；
6. 任意边缘实例可以继续处理。

必须覆盖：

- 普通表单；
- destructive 操作确认；
- URL mode OAuth/外部操作；
- 权限升级确认；
- 超时、取消和重复提交；
- `requestState` 篡改拒绝。

## 五、Tasks 扩展用于长时间工作

大乘小程序中的以下工作应优先使用正式 Tasks 扩展：

- 插件构建；
- 安全扫描；
- Cloudflare 部署；
- provenance 和签名生成；
- 市场审核流水线；
- 批量发布；
- 大文件处理；
- 长时间 MCP 工具调用。

生命周期使用：

- 服务端决定何时把 `tools/call` 转为 task；
- 返回 task handle；
- 客户端调用 `tasks/get`；
- 必要时调用 `tasks/update`；
- 用户可调用 `tasks/cancel`；
- 不实现不安全的全局 `tasks/list`；
- task 必须绑定发布者、用户、插件和权限范围；
- task 状态保存在显式持久层，不依赖 MCP session。

大乘现有自动化队列和 Actions 任务不等同于 MCP Tasks，但可以通过适配层把发布任务状态暴露为 MCP Tasks，让小程序 UI 和 CLI 使用统一生命周期。

## 六、授权和身份升级

对远程 MCP 服务必须落实 MCP `2026-07-28` 的 OAuth/OIDC 加固：

- 校验授权响应的 `iss`；
- 凭证绑定授权服务器 issuer；
- 资源迁移到不同 issuer 时重新注册或授权；
- 正确处理 OIDC `application_type`；
- 正确申请和轮换 refresh token；
- 权限 step-up 不得静默扩大 scope；
- 市场签名身份、MCP OAuth 主体和插件发布者身份可审计关联；
- 每个插件独立授权边界，不共享第三方插件写权限或 Secret。

平台托管发布使用 GitHub Actions OIDC 的短期发布凭证，与 MCP 用户授权是两个不同信任域，不能混用。

## 七、JSON Schema 2020-12

大乘 SDK、表单生成器和校验器必须支持工具完整 JSON Schema 2020-12，至少包括：

- `$defs` / `$ref`；
- `oneOf` / `anyOf` / `allOf`；
- `if` / `then` / `else`；
- enum、const 和默认值；
- 任意 JSON 类型的 output schema；
- 任意 JSON 类型的 `structuredContent`。

安全限制：

- 不自动读取外部 `$ref` URL；
- 限制 schema 深度、节点数和验证时间；
- 表单无法表达的 schema 必须安全降级为 JSON 编辑器或文本模式；
- 服务端始终执行最终校验，不能信任 UI 校验。

## 八、旧能力迁移

### Roots

不再把 Roots 作为新插件设计基础。改用：

- tool 参数中的 workspace ID；
- 明确 resource URI；
- 插件配置；
- 宿主授予的 scoped filesystem capability。

### Sampling

新远程插件不得依赖 MCP Sampling 作为核心功能。需要模型调用时：

- 由大乘宿主执行模型能力；或
- 插件后端直接集成允许的模型提供商；
- 明确计费、数据流和用户授权。

### Logging

- 远程插件：OpenTelemetry；
- 本地 stdio 插件：stderr；
- MCP Logging 仅作为兼容能力，不作为唯一日志通道。

### SSE

旧 HTTP+SSE 和 sessionful Streamable HTTP 保留为临时兼容通道，不得用于新插件模板。迁移完成后按遥测数据逐步关闭。

## 九、市场元数据扩展

每个插件版本的市场元数据增加：

```json
{
  "mcp": {
    "recommendedProtocolVersion": "2026-07-28",
    "supportedProtocolVersions": ["2026-07-28", "2025-11-25", "2025-06-18"],
    "endpoint": "https://plugin.example/mcp",
    "stateless": true,
    "extensions": {
      "io.modelcontextprotocol/apps": "1.x",
      "io.modelcontextprotocol/tasks": "1.x"
    },
    "capabilitiesDigest": "sha256:...",
    "toolListTtlMs": 300000,
    "legacyEndpoint": "https://plugin.example/mcp/legacy"
  }
}
```

实际 extension ID 和版本以正式扩展规范为准，不得把示例值直接硬编码到生产。

市场审核应验证：

- `server/discover`；
- 协议版本协商；
- 声明与实际能力一致；
- tool/UI resource 不可变性；
- CSP；
- app-only 工具不可被模型直接发现；
- Tasks 授权范围；
- trace context；
- legacy fallback；
- 不存在 session fixation、跨用户 task 泄漏或缓存污染。

## 十、实施阶段

### 阶段 A：协议兼容层

- 增加统一 MCP transport abstraction；
- 实现 `server/discover`；
- 实现 2026 与旧协议自动协商；
- 保持当前小程序可用；
- 建立跨协议 conformance tests。

### 阶段 B：Cloudflare 无状态服务模板

- 升级 Cloudflare Agents SDK；
- 使用 SDK v2 server factory；
- 新增 `createMcpHandler` 无状态路径；
- 为现有会话功能保留临时 legacy lane；
- 去除普通工具对 Durable Object / session 的依赖。

### 阶段 C：大乘宿主 MCP Apps

- 用官方协议替换自定义 iframe bridge；
- 实现 AppBridge、安全沙箱、CSP、host context 和 display modes；
- 保持文本降级；
- 同一 UI 在 Web、桌面和移动端验证。

### 阶段 D：MRTR 和 Tasks

- 将 elicitation 改为 MRTR；
- 将发布、部署和扫描接入 Tasks；
- 接通 UI、CLI 与任务状态；
- 验证取消、恢复、权限和跨边缘实例继续执行。

### 阶段 E：缓存、路由、授权和观测

- `Mcp-Method` / `Mcp-Name` 网关策略；
- ttl/cacheScope；
- OTel trace；
- OAuth/OIDC 加固；
- JSON Schema 2020-12；
- 安全和负载测试。

### 阶段 F：逐步退出 legacy

- 统计协议版本和 legacy 使用率；
- 发布弃用通知；
- 先停止新插件创建 legacy 服务；
- 再关闭无活跃依赖的 legacy 路由；
- 不得一次性破坏旧客户端。

## 十一、强制验收

任务必须提供以下真实证据：

1. 一个真实 Cloudflare Worker 插件实现 `server/discover` 和 MCP `2026-07-28`。
2. 连续工具调用不产生或依赖 `Mcp-Session-Id`。
3. 请求可由无粘性、无共享 transport session 的边缘实例处理。
4. 新宿主可连接新服务，也能回退连接旧服务。
5. 旧客户端可通过兼容路径使用新服务的普通工具。
6. 至少一个工具提供标准 `ui://` MCP App。
7. 大乘 Web、桌面或移动宿主通过标准 AppBridge 渲染该 UI。
8. 不支持 MCP Apps 的测试客户端能够获得文本降级结果。
9. CSP 阻止未声明域名请求，iframe 无法读取宿主 DOM、cookie 或 storage。
10. 至少一次 elicitation 使用 MRTR 完成，并验证取消与篡改拒绝。
11. 至少一个长时间发布或部署操作通过 Tasks 扩展完成。
12. `tasks/get`、`tasks/update`、`tasks/cancel` 权限隔离有效。
13. `tools/list` 或 UI resource 的 `ttlMs` / `cacheScope` 行为经过测试。
14. `Mcp-Method` / `Mcp-Name` 可用于 Cloudflare 路由、限流和日志聚合。
15. 一次端到端调用在 OpenTelemetry 中形成可关联 trace。
16. Tool schema 覆盖 JSON Schema 2020-12 组合和条件结构。
17. OAuth/OIDC `iss`、issuer 绑定和 scope step-up 测试通过。
18. Roots、Sampling、Logging 和旧 SSE 不再是新插件模板的默认依赖。
19. GitHub Actions 执行新旧协议 conformance、Cloudflare 生产构建和真实端到端测试。
20. 最终报告列出协议版本、Cloudflare 部署 URL、插件 ID/版本、Actions run、MCP Apps、Tasks、MRTR、缓存、追踪和兼容性证据。

只改文档、只升级依赖、只替换版本字符串、只通过本地 mock，均不算完成。

## 十二、预期收益

完成后，大乘小程序可获得：

- 真正适合 Cloudflare 全球边缘网络的无状态 MCP；
- 不再依赖 sticky session 和共享 transport session store；
- 降低 Durable Object、KV 和长连接成本；
- 工具级边缘路由、限流和安全策略；
- 可缓存的工具清单和不可变 UI；
- 标准化 MCP Apps，一次开发可进入多个兼容宿主；
- 用 Tasks 统一长时间发布和部署体验；
- 用 MRTR 在无状态环境完成用户确认；
- 更完整的 OAuth/OIDC、CSP、权限和审计模型；
- 端到端可追踪的生产观测；
- 对旧客户端平滑迁移，而不是强制一次性升级。

这次 MCP 升级应作为大乘小程序市场架构的核心组成部分，而不是独立的协议兼容补丁。
