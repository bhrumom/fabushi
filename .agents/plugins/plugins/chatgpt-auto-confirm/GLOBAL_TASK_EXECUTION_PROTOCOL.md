# ChatGPT 自动确认小程序｜全局任务执行协议

## 适用范围

本协议不是某一个项目任务规范，而是 ChatGPT 自动确认小程序处理所有动态新增任务时的通用执行流程。

任何新任务，无论属于哪个项目，都必须遵循本流程。

## 1. 新任务输入方式

用户只需要提供任务来源，例如：

- Gmail 中某一封邮件；
- Google Drive 中某个任务文件；
- Google Calendar 中某个任务安排；
- GitHub Issue/PR/仓库任务。

ChatGPT 自动确认小程序必须先定位该任务来源，不要求用户重复复制完整需求。

例如：

“执行 Gmail 里面 XX 邮件的任务。”

执行流程：

Gmail 邮件
→ 读取邮件正文、附件、关联文件
→ 提取目标、范围、验收标准、截止时间
→ 建立/更新任务记录
→ 执行任务
→ 回写结果。

## 2. 所有任务统一管理模型

所有任务必须进入统一任务管理系统：

项目
→ 阶段
→ 原子任务
→ 自动验收
→ 汇报记录。

不得只在聊天窗口临时执行而没有任务记录。

## 3. 执行前读取顺序

每次开始任务：

1. 读取 Google Sheets 总控表中的任务状态；
2. 读取任务来源（邮件/文件/日历）；
3. 读取关联 Drive 文档；
4. 读取 Calendar 时间安排；
5. 检查 GitHub/代码/Actions（如任务涉及开发）。

## 4. 任务执行要求

每个任务必须拆解为可验证步骤：

- 做什么；
- 修改什么；
- 产生什么结果；
- 如何自动验证；
- 验证失败如何处理。

涉及代码任务时必须建立对应：

- Git commit；
- Pull Request；
- GitHub Actions check；
- 测试结果；
- Release 或部署证据。

## 5. 完成判定

任务不能根据主观判断完成。

必须满足：

实现完成
+
自动测试通过
+
证据记录完成

才可以标记完成。

## 6. 执行后回写

每轮执行结束必须更新：

Google Sheets：
- 状态；
- 进度；
- 完成内容；
- 阻塞；
- 下一步；
- 验收证据。

Gmail：
- 发送必要汇报；
- 邮件只引用统一任务总控表，不重复维护状态。

Google Drive：
- 保存长期文档和验收材料。

Google Calendar：
- 更新后续执行安排。

GitHub：
- 保存代码事实和自动验收事实。

## 7. 动态新增任务

新增任务时，不需要重新设计流程。

只需要：

1. 用户提供任务来源（例如邮件）；
2. 自动确认读取邮件；
3. 创建任务记录；
4. 拆解原子任务；
5. 安排时间；
6. 执行；
7. 自动汇报。

## 8. 全局优先级

该协议适用于所有未来 ChatGPT 自动确认任务。

具体项目任务规范可以增加更严格要求，但不得降低本协议要求。
