# Fourth round — independent review hardening

Project `FAB-P0003 / FCM`; task `FCM-FAST-20260911`; PR #2503.

## Trigger

Independent Codex review of head `d8083c3f024373ba0f6fc4fa003511734ecdd1d8` found three P2 fail-closed gaps even though the exact-head Actions suite was green:

1. Required UI checkpoint names did not require their declared MIME type to match PNG/JSON, so malformed or mislabeled evidence could bypass format validation.
2. The pull-request job checked out PR-head code and then supplied `github.token` to the head-controlled `pr_inventory.py` script.
3. Multi-package Cargo suites accepted one generic non-zero `test result` line, so one selected package could theoretically execute zero tests while another package made the aggregate pattern pass.

A green run is not acceptance when independent review exposes a correctness or trust-boundary defect.

## Repairs pushed

- `2e96bbde74b158a0c2535786c44dbd6125d6713b`: token-backed PR inventory is limited to trusted canonical `push` events on `refs/heads/main`; PR and merge-group head code does not receive the token through that script.
- `6d1ca99a884dd88255b9babafd73ab8fbac10bab`: required checkpoint PNG/JSON, WebM video and trace attachments require exact MIME identities before payload validation; duplicate attachment names fail closed.
- `f3e2903afaef40491ce0a3707ae353013c52c4cf`: split the Rust registry to one selected Cargo package per suite so every claimed package must independently prove non-zero test execution.
- `8dad56ef8d5a6c08e1506bc2e22649639a711121`: the controller rejects future multi-package `cargo test` suite definitions.
- `7102e01467d1678046d8336390dcdcd1288e8e82`: added the controller regression locking the one-package-per-suite policy.
- `8a1f8e3a7aee62035e36d7bd332526d0efca690f`: added evidence regressions for required MIME mismatch and duplicate attachment names.

The three review threads were replied to with the exact repair semantics and explicitly left contingent on a new exact-head Actions pass.

## Acceptance state

The branch implementation is hardened, but this round is **not yet accepted** merely from source inspection. Required next evidence is a successful exact-head `Fabushi CLI-first fast feedback` run after these repairs, plus the repository's other required PR governance gates and independent review readback. Protected merge and canonical-main validation remain pending; no release or all-platform acceptance is claimed.
