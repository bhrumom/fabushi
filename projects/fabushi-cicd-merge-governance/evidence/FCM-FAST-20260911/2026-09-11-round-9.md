## Review findings and repairs

### P1 — Telegram media product gate could be bypassed at protected enqueue

The Messaging Product Gate itself triggers for `native/telegram-media/**`, but the automerge `messagingPathPrefixes` did not include that path. A media-only PR could therefore have been enqueued after base CI without waiting for its selected media/product gates.

Repair:

- `82e5010960886b7b236bfddd83040960ac024e41` adds `native/telegram-media/` to the automerge Messaging Product Gate dependency boundary.
- `f7513ab560c6ae062f328efb2026f75b99b2249a` adds a contract regression that asserts the media + Mahayana boundaries and path-aware fast/product prerequisites remain present.

A transient pull lookup typo introduced while editing the automerge workflow was detected before acceptance and repaired by `8807344360ff0d7fcf9d7680d7fa295ce20b9425`; the same contract regression now locks the sensitive-change lookup shape.

### P2 — exact-source proof ignored non-ignored untracked files

The previous tracked diff check could not detect a selected suite creating an untracked source/config file that a later suite consumed.

Repair:

- `1f6e9c246862073eab2e92892e91cfcfa27be22d` adds `git ls-files --others --exclude-standard -z` provenance checks, rejects non-ignored untracked paths outside explicitly owned evidence directories, verifies provenance after every suite before the next suite can run, and requires every planned suite to execute before a layer can pass.
- `6826bf69e0ae0ace38d400551dd7eab61d726845` adds a real temporary-Git-repository regression proving `generated.rs` is rejected while an explicitly owned `.fast-test-results/...` artifact is allowed.
- `294a565bf4b9584c95a3bd04b250873072e07679` sets `PYTHONDONTWRITEBYTECODE=1` in the fast workflow so controller imports/tests do not create Python cache files that contaminate provenance.

### P2 — indexed PNG evidence could omit its mandatory palette

The stdlib PNG verifier validated CRC/raster structure but did not require `PLTE` for indexed-color PNG.

Repair:

- `1dfc710b449bafc929086c116b0f8c8f69c9f11d` enforces `PLTE` ordering/uniqueness/size, requires it for color type 3, validates palette capacity against bit depth, rejects it for grayscale, and rejects unknown critical chunks while still allowing ancillary chunks.
- `324134fb3f5edadb4c942e2a537fe5dc429fce7a` adds a regression that accepts a valid 1-bit indexed PNG with a palette and rejects the same raster when `PLTE` is missing.
