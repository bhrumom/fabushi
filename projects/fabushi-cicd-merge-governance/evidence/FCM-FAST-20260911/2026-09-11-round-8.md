# Eighth round — make fast feedback blocking and reduce warm UI setup

Project `FAB-P0003 / FCM`; task `FCM-FAST-20260911`; PR #2503.

## Why this round exists

After repairing the independent-review P1, the protected automerge controller was audited against the newly added fast-feedback workflow. It required `CI`, and conditionally Messaging Product Gate / Electron desktop quality, but did not require `Fabushi CLI-first fast feedback`. That meant the new fast controller could report a failure while an otherwise-green affected PR still entered the protected merge queue. A Shopify-like rapid feedback lane is useful only if its scoped failures actually stop integration.

## Blocking fast feedback

Commit `d329b407fe1e42bf4ee1d0b594f30894e770742f` updates `.github/workflows/automerge.yml`:

- `Fabushi CLI-first fast feedback` is now a watched `workflow_run`, so completion re-evaluates an authorized PR;
- the automerge controller uses the same affected path boundary as `.github/workflows/fcm-fast-feedback.yml`: `tools/fabushi-test/**`, `desktop/**`, `native/mahayana-messaging/**`, the Mahayana Rust workspace, relevant frontend host/lib/packages paths, and the fast-feedback workflow itself;
- an affected PR must have a successful exact-head `Fabushi CLI-first fast feedback` run before it can be enqueued;
- unrelated PRs are not globally forced to run this path-filtered workflow.

This keeps the normal protected merge queue and merge-group revalidation. It does not convert the fast subset into full native/package/release acceptance.

## Faster warm UI lane

Commit `6ffca7681604bed09007ff4f962a6a2a7a12440d` updates `.github/workflows/fcm-fast-feedback.yml` so the headless UI lane caches `~/.cache/ms-playwright` keyed by OS and `desktop/package-lock.json`. `npm ci` now uses `--prefer-offline`, and Playwright still runs `install --with-deps chromium` so system dependencies remain explicitly satisfied while an unchanged Chromium payload can be reused on warm runners/cache restores.

The existing npm cache, Rust cache, exact-SHA checkout, contract/core/UI parallel matrix, structured failure evidence and 90-day artifacts remain intact.

## Acceptance state

These changes are source-complete but not yet accepted. The final candidate still requires fresh exact-head GitHub Actions, exact-head independent review, and protected merge-queue revalidation. Earlier successful runs are historical evidence only. No current-head success is claimed until GitHub reports it.
