# Fifth round — restore and make the Messaging Product Gate change-aware

Project `FAB-P0003 / FCM`; task `FCM-FAST-20260911`; PR #2503.

## Why this round exists

The protected automerge path still expects `Messaging Product Gate` for messaging-sensitive changes, but the workflow had been temporarily reduced to manual `workflow_dispatch` on 2026-09-05 for a Mac-only test release. Leaving that state in place prevents a fully automatic protected delivery loop. Deleting or bypassing the gate would reduce safety, so this round restores automatic execution instead.

## Implementation

`.github/workflows/messaging-product-gate.yml` now:

- runs automatically for relevant pull requests and canonical-main pushes, while retaining manual dispatch;
- checks out the exact PR head / push SHA with persisted credentials disabled;
- computes the exact base-to-head changed paths and fails closed to all product lanes when the base cannot be proven, the relevant diff is unexpectedly empty, an unknown relevant path appears, or the gate definition itself changes;
- selects four independently parallelizable domains: native messaging, Telegram media, Mahayana host/social bridge, and Electron messenger contract;
- preserves the historical dependency closure for messaging/media changes while allowing narrower host-only or desktop-only changes to avoid unrelated work;
- retains the historical messaging/media fmt, test and Clippy checks, the historical three-package Mahayana host/social tests, and the historical Electron contract checks;
- adds exact-source and tracked-source-drift rejection to the selected lanes;
- aggregates selected-success / unselected-skipped states fail closed.

## Failed first restoration attempt and correction

The first restored run on exact head `55c2c2084913b59aaa04137d2daa1dac1f65d2a4` successfully exercised impact selection and passed native messaging, Telegram media, and Electron contract lanes. The Mahayana host lane passed its tests but failed an additional per-package Clippy step that this round had introduced beyond the historical workflow. `mahayana-feature-host` reaches `mahayana-live-toolkit`, whose compile-time contract requires an explicit single store-backend feature; default package Clippy did not define that feature mode.

Reading the pre-pause Product Gate back from GitHub established that the historical host portion ran tests for `mahayana-host-protocol`, `mahayana-feature-host`, and `mahayana-social`; it did not run Feature Host Clippy. The correct recovery is therefore to preserve those historical tests rather than silently invent a default Clippy feature mode. The extra host Clippy was removed in commit `3b46779d8826cc4c0c576ebd18d559a923d48357`. A future Feature Host Clippy optimization must define and verify an explicit feature matrix as a separate acceptance change.
