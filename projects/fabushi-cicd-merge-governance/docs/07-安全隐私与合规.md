# 安全、隐私与合规

## Security boundaries

- `main` is the protected delivery source of truth.
- GitHub Actions token permissions use least privilege per workflow/job where practical.
- Store credentials, signing certificates, provisioning profiles and service-account material remain GitHub Secrets/Variables; they must never be copied into project records or artifacts except the signed distributable outputs themselves.
- Release-source gate validates exact source SHA and required quality gates before signing/upload.
- CI/CD workflow changes, auth/payment/database paths and release scripts are treated as Tier 3 sensitive changes.

## Threats addressed

| Threat | Control |
|---|---|
| Releasing an unreviewed branch SHA | protected-main ancestry check |
| Releasing a SHA without platform tests | `CI result` + Electron/native quality gate requirement |
| CI speed optimization bypasses tests | unknown runtime paths fail safe; aggregate result retained |
| Direct merge bypass | merge queue remains canonical |
| Unowned sensitive workflow change | narrow CODEOWNERS rules |
| Secret leakage | no credentials in repository/project evidence; Actions secrets only |

## Privacy

The latency observer records repository workflow metadata (run id, event, selected jobs, SHA, timestamps and URL). It does not ingest application user data or secret values.

## Supply-chain considerations

Third-party Actions remain pinned by major/version according to existing repository conventions. Workflow guardrails and PR review cover changes to those dependencies. Future policy may pin immutable action SHAs if the repository adopts that requirement globally.
