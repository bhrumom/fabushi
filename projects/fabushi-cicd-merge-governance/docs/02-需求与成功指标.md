# 需求与成功指标

## 稳定需求

| ID | Requirement | Success metric |
|---|---|---|
| FCM-R001 | CI 按真实变更影响域执行最小必要验证 | 文档/治理 fast path 不运行无关产品 suites；未知非文档路径 fail-safe |
| FCM-R002 | merge queue 保留并对 merge-group 候选重新验证 | `CI result` 在 PR head 与 merge group 均成功后才进入 `main` |
| FCM-R003 | CI 延迟可持续观测 | 自动统计 validation surface、P50/P95、queue delay，并保留 JSON/CSV 证据 |
| FCM-R004 | 商店/发布只接受受保护主干上的已验证源提交 | Apple/Google delivery 在构建/上传前验证 protected-main ancestry 和平台质量 gates |
| FCM-R005 | 敏感交付路径有明确所有权，低风险路径不增加无意义审批 | CODEOWNERS 只覆盖敏感面；无 repository-wide catch-all |
| FCM-R006 | 生产 CD 与产品影响域一致 | 无关 main 变更不触发 Worker/Pay 重部署 |
| FCM-R007 | 项目治理状态与真实 GitHub 证据一致 | WBS/验收/状态/证据在 merge 后同步并核对 `main` |
| FCM-R008 | PR CI 只运行快速检查，不运行重型 E2E/安装包/Debug 包 | PR/merge-group workflow 中 heavy package/E2E jobs 不启动；required aggregate gate 仍存在 |
| FCM-R009 | `main` 合并后按影响域运行安装包、Debug 包与 E2E | 受影响 Electron/macOS/Windows/Linux/Android/iOS 平台执行 post-main heavy gate；无关平台跳过 |
| FCM-R010 | 全平台构建可跨 GitHub Actions run 增量复用上一轮结果 | Node/Cargo/Gradle/Xcode/Electron/native outputs 均有显式版本化缓存与安全失效规则 |
| FCM-R011 | 缓存 miss 能无损回退为可重复 clean build | 任一缓存缺失/驱逐/版本变化时仍能从源代码成功完成对应构建与测试 |
| FCM-R012 | 构建缓存收益可观测 | 记录 cache hit/miss、cold/warm duration；同平台连续小改动 warm build 目标较 cold build 降低 >=50% |

## CI latency SLO

初始预算以 GitHub-hosted runner 墙钟时间为准：

- fast-path P95: `<= 30s`
- workflow-governance P95: `<= 120s`
- single-domain P95: `<= 900s`
- multi-domain P95: `<= 1200s`
- full-canonical P95: `<= 1800s`

样本少于 5 个时只报告 `insufficient-samples`，不得伪造趋势或为了达标跳过安全检查。

## FCM-009 build/test efficiency SLO

- PR fast lane：目标不包含任何安装包、Debug package 或 E2E job。
- post-main heavy lane：仅对受影响平台运行。
- warm build：在工具链/锁文件不变、仅小范围源码变化的连续两次 Actions run 中，目标墙钟时间较 cold build 至少下降 50%。
- cache correctness：任何 cache miss/eviction/schema bump 都必须正确回退到 clean build，不允许以陈旧缓存换取速度。
