# 完成定义与验收 — FAB-P0003

FAB-P0003 只有在以下所有 required gates 都有客观证据时才可标记完成。

## G0 — Fast safe merge

1. `merge_group` 不再无条件强制所有 canonical product CI jobs。
2. PR / merge-group 使用正确 base/head SHA 做 impact classification。
3. docs/project/governance fast path 仍产生 required `CI result`。
4. unknown non-doc runtime path fail-safe 到全量 canonical checks。
5. workflow changes 仍运行 architecture/workflow guardrails。
6. automerge 只授权 GitHub protected merge；不直接 REST merge `main`。
7. Worker/Fabushi Pay CD 对无关 main 变化在轻量 impact resolver 后退出。
8. FCM-001/FCM-003 的 PR、CI、merge-queue 和 canonical-main evidence 已记录。

## G1 — CI latency observability

9. `CI latency observability` 可 schedule/manual/相关 PR 触发，且不 checkout 产品代码。
10. observer 读取真实 Actions runs/jobs，输出 validation surface、P50/P95、queue P50/P95。
11. JSON/CSV artifacts 和 workflow summary 可复核。
12. 样本少于 5 明确显示 `insufficient-samples`；telemetry 为 soft SLO，不替代 required checks。
13. observer 的 PR workflow 实际成功并记录 run/artifact evidence。

## G2 — Release promotion safety

14. Apple/Google store workflows 解析 exact SHA，并验证 SHA 位于 protected `main` 历史。
15. macOS 在 build/sign/upload 前要求 exact SHA 的 `CI result` + `Electron desktop result`。
16. iOS/Android 在 build/sign/upload 前要求 exact SHA 的 `CI result` + `Native mobile result`。
17. Apple `both` 要求三项 canonical gates 全绿。
18. delivery workflow 保持 manual dispatch；GitHub Release 指向 delivered source SHA。
19. `Delivery governance contract` 实际成功并验证上述静态不变量。

## G3 — Policy automation

20. `.github/CODEOWNERS` 对 CI/CD、scripts、release governance、payment 等敏感面有明确 owner。
21. 不存在 repository-wide catch-all CODEOWNER，避免给普通低风险变更增加治理审批税。
22. automerge sensitive prefixes 和 merge-queue policy 保持有效。
23. ownership/release governance contract 在 PR 上实际成功。

## Project closure

24. 项目文件夹满足企业标准：OWNERS、source、charter/scope/requirements/architecture/quality/release/SLO/security/DoD、roadmap/WBS/milestones/acceptance/risks/status/dependencies/changelog/issues、tasks、ADRs、evidence、runbooks 均存在并有效。
25. 实现 PR 的 required `CI result` 成功；敏感 change 通过 protected merge queue 落入 `main`。
26. merge 后重新读取 canonical `main`，确认 observer、release gate、store workflows、CODEOWNERS、project metadata 与记录一致。
27. FCM-002/004/005/006 task record、WBS、milestones、acceptance matrix、status report、changelog、risk/dependency/action registers、evidence indexes 全部同步为事实状态。
28. `PROJECT.yaml`/README 只有在全部上述条件满足后才可改为 completed/closed。

任何 pending/failed required check、未合并 PR、未验证 main 或缺失 evidence 都阻止项目完成声明。
