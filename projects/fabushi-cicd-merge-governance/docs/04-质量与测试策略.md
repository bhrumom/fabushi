# 质量与测试策略

## 原则

- 所有重型编译、打包、集成/E2E 均在 GitHub Actions 运行；本地只允许轻量文本/配置审查。
- required check 的真实性优先于速度；优化通过 impact selection、并行、缓存和避免重复工作实现。
- workflow/governance 变更必须至少通过 canonical `CI result` 中的 workflow guardrails。

## 验证层次

| Layer | Verification |
|---|---|
| Impact classification | PR / merge-group exact diff selection，未知非文档路径 force-all |
| Aggregate safety | `CI result` 必须成功 |
| Workflow governance | `Canonical architecture guardrails` |
| Delivery governance | `Delivery governance contract` |
| CI telemetry | `CI latency observability` 产出 JSON/CSV + summary |
| Electron | `Electron desktop result` |
| Native mobile | `Native mobile result` |
| Store delivery | release source gate + signing/build/upload workflow evidence |

## FCM-002 验收

- observer 从 Actions API 读取最近 CI runs/jobs，不 checkout 产品代码。
- validation surface 分类与 P50/P95 计算可在 workflow summary 与 artifacts 中复核。
- 样本不足时状态为 `insufficient-samples`。

## FCM-004 验收

- Apple：macOS 要求 `CI result` + `Electron desktop result`；iOS 要求 `CI result` + `Native mobile result`；both 要求三者全部成功。
- Google Play：Android 要求 `CI result` + `Native mobile result`。
- exact source SHA 必须属于 protected `main` 历史。

## FCM-005 验收

- CODEOWNERS 覆盖 CI/CD、scripts、release governance、payment 等敏感面。
- 不允许 repository-wide catch-all owner。
- governance contract 对关键 ownership/release/merge invariants 做静态校验。
