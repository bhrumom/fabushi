# 架构与实现策略

## 当前目标架构

```text
change
  -> PR
  -> change classifier
  -> selected canonical checks
  -> CI result
  -> protected merge queue
  -> merge-group classifier/checks
  -> main
  -> impact-aware CD / manual store delivery
  -> source ancestry + release gate verification
  -> build/sign/upload
  -> immutable release evidence
```

## 关键组件

- `.github/workflows/ci.yml`: canonical impact classifier + aggregate `CI result`.
- `.github/workflows/automerge.yml`: 只授权 GitHub protected merge，不直接绕过 main 保护。
- `.github/workflows/ci-latency-observability.yml`: 只读 Actions metadata 的 SLO observer。
- `.github/scripts/require-release-source-gates.sh`: 商店发布源提交门禁。
- `.github/workflows/apple-store-delivery.yml`: macOS Electron + native iOS 手动发布。
- `.github/workflows/google-play-delivery.yml`: native Android 手动发布。
- `.github/CODEOWNERS`: 敏感路径 ownership。
- `.github/workflows/delivery-governance-contract.yml`: 静态验证 release/ownership/merge invariants。

## 设计约束

1. fast path 只能减少无关工作，不能绕过 required aggregate check 或 merge queue。
2. 未分类 runtime path 一律 fail-safe。
3. telemetry 为 soft SLO，不成为主干保护单点故障。
4. store delivery 必须验证 exact SHA；构建出的 signed package 和 GitHub Release 必须指向同一 SHA。
5. CI/CD、auth、payment、database 与 release infrastructure 视为 Tier 3 敏感面。
6. 本项目不在开发机执行重型 build/test；GitHub Actions 是重型验证事实来源。
