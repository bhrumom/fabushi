## Objective

Make the Mahayana CLI/test-driver layer the first-class fast correctness surface for ordinary product-logic pull requests, while keeping packaged UI testing as an independent semantic/evidence layer. The change must improve feedback architecture without weakening exact-main packaged E2E or release gates.

## Implementation

- `.github/workflows/mahayana-fast-checks.yml`
  - adds `cargo test -p mahayana-cli --profile ci --no-default-features` before broader compatibility suites;
  - adds `cargo test -p mahayana-test-driver-protocol --profile ci` immediately after the CLI gate;
  - preserves existing sparse checkout, `CARGO_INCREMENTAL=1`, `Swatinem/rust-cache@v2`, affected-path triggers and superseded-run cancellation.
- `chatgpt-vps-control/tests/mahayana-cli-fast-gate-contract.test.js`
  - locks the CLI/test-driver steps and their ordering;
  - locks the fast-path primitives and rejects accidental `cargo test --workspace` expansion.
- `.github/workflows/ci.yml`
  - runs the new contract under the existing 3-minute required CI job.

## Known remaining performance gap

The existing macOS packaged interactive workflow can still wait up to 1500 seconds for external `@fabushi test` completion after the installed App has registered its local semantic App Agent surface. This task does not pretend that latency is solved. A follow-up should self-drive the packaged semantic smoke/full journey from the GitHub Actions host through the existing private loopback App Agent bridge, then retain remote MCP as an optional interactive/debug path rather than a mandatory idle wait.

Do not mark FCM-010.9 passed until the branch is protected-merged and the resulting exact source has objective Actions evidence for the direct CLI and test-driver steps.
