## Generation-race repair round

Scope is intentionally narrow. Do **not** redo FCM-010.13.8-.10 and do not weaken the frozen-source, immutable-tag, exact-device, 27-category, or final logout evidence gates.

Required implementation contract:

1. Centralize generation-sensitive `fabushi.app.action` recovery in the production external controller so every action path, including direct journey actions, is covered.
2. On `stale_app_surface_generation`, fail closed unless the target can be stably re-resolved. For a stable `agentId` (or stable `agent:<id>` ref), call `fabushi.app.find` again, require exactly one matching semantic target, take the **new** returned generation, and retry the action. Never retry an action with the same stale generation merely because a delay elapsed.
3. Bound retries; exhaustion or ambiguous/non-stable target resolution remains an error.
4. Add a deterministic controller regression in which the first semantic find/action pair uses generation `95`, action reports `expected 96, received 95`, the retry performs a second find returning `96`, and the successful action is proven to use generation `96`.
5. Preserve exact device identity `gha-<run>-<attempt>-macos-app`, frozen source `7ee12b790e18049d2b9509b0c29128dd2ace690b`, immutable tag `desktop-1.2.56-7ee12b790e18`, all 27 categories, and `READY_FOR_LOGOUT PASS → ci_session_finish → fresh App snapshot → exact settings-logout` ordering.

### Open-source-first evidence

The repair follows established stale-element handling rather than inventing a weaker retry model:

- Playwright Locator semantics re-resolve the current DOM element for each action and retry instead of retaining a stale element handle (`https://playwright.dev/docs/locators`, `https://playwright.dev/docs/api/class-locator`). Adaptation: re-run Fabushi semantic `find` and rebuild the action with the returned generation/target on every stale retry.
- Selenium documents stale element references as invalid after DOM replacement and requires re-location / retry rather than reuse (`https://www.selenium.dev/documentation/webdriver/troubleshooting/errors#stale-element-reference-exception`). Adaptation: only retry when Fabushi can re-resolve a stable semantic target; otherwise fail closed.
- No new external runtime dependency is required; this is a bounded controller-layer protocol correction.
