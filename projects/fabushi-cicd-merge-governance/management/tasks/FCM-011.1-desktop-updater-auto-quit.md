## Objective

Fix the packaged desktop update lifecycle where the new release is downloaded/staged but Fabushi remains running until the user manually quits, after which the new version appears on relaunch.

## Root cause

Fabushi's production `BrowserWindow` close handler intentionally calls `preventDefault()` and hides the window to preserve background presence. `electron-updater` / Squirrel.Mac also closes the app during `quitAndInstall`. That updater-owned close can therefore be converted into hide-to-background before the existing `before-quit` update-install exception can take effect.

## Open-source-first evidence

Inspected upstream `electron-userland/electron-builder` `MacUpdater.ts` (MIT). Its macOS path expects native Squirrel update completion to be followed by application quit/relaunch; Fabushi should not substitute its normal background-hide behavior for that updater-owned close.

## Implementation

- Add `desktop/electron/update-quit-guard.cjs` to install a one-shot compatibility guard around Electron's native updater quit path.
- Wire the guard before `main.cjs` loads from `desktop/electron/bootstrap.cjs`.
- Preserve ordinary background-persistence close behavior.
- Remove the one-shot bypass if native `quitAndInstall` fails synchronously.
- Add `desktop/electron/update-quit-guard.test.cjs` regression coverage.
