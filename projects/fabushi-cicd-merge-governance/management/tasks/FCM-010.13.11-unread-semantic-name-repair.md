## Open-source-first survey and provenance decision

Survey performed on 2026-09-12 before accepting this custom semantic-surface repair as the final design. The task is narrow — expose a deterministic two-state unread semantic signal through Fabushi's existing React DOM/App Surface boundary — so the survey focused on mature projects that already solve state exposure and stable UI query problems rather than generic component libraries.

### Candidate 1 — Radix Primitives (`radix-ui/primitives`)

- **Canonical repository:** https://github.com/radix-ui/primitives
- **License / maintenance:** MIT; maintained by WorkOS; active releases and provenance-attested package publishing.
- **Architecture / data model:** Radix explicitly models component state as a finite set of predefined string states and exposes that state on the DOM through `data-state`. Its design philosophy prefers deterministic enum-like state over ad-hoc booleans and supports both controlled and uncontrolled React state.
- **API / operational edge cases:** state is attached to the component DOM boundary rather than inferred from visual text. This survives presentation changes and avoids parsing rendered copy. Controlled/uncontrolled ownership is explicit, which is relevant to Fabushi because unread is owned by the peer model while the semantic projection is a view of that state.
- **Test / security posture:** the state exposure is machine-readable without requiring message contents, badge numbers, credentials, or other sensitive text to be copied into an automation channel. Radix's repository uses component tests and visual regression infrastructure and is a mature accessibility-focused React project.
- **Fabushi compatibility:** high at the design level because Fabushi's Electron UI is React and already exposes stable DOM attributes (`data-agent-id`) to its App Surface. Adding Radix as a runtime dependency solely for this two-state projection would be disproportionate and would not replace Fabushi's existing App Surface protocol.
- **Decision:** **adapt the proven design, do not copy code or add the dependency.** Preserve a stable semantic node and expose the unread state as exact finite strings (`unread-none`, `unread-positive`) at that boundary. This is a design-level reuse of the explicit-enum-state pattern, implemented inside Fabushi's existing `BotMark`/App Surface boundary.

### Candidate 2 — Microsoft Playwright (`microsoft/playwright`)

- **Canonical repository:** https://github.com/microsoft/playwright
- **License / maintenance:** Apache-2.0; actively maintained; the repository contains browser, Electron, installation, stress and end-to-end test projects.
- **Architecture / API:** Playwright's locator layer separates stable selector contracts (`getByRole`, `getByTestId`, label/text/title locators, etc.) from application implementation details. Fabushi already uses packaged Playwright evidence, so this is an existing compatible test boundary rather than a new dependency proposal.
- **Test / operational edge cases:** Playwright's locator model reinforces that automation should resolve a deterministic semantic target rather than parse screenshots or positional UI. It is useful for independently proving that the packaged App Surface exposes the expected semantic state, but it is not the production source of unread state.
- **Security posture:** using stable semantic/test selectors avoids screen scraping and does not require exposing account secrets. Production redaction remains authoritative; tests only assert the bounded semantic contract.
- **Fabushi compatibility:** already compatible and already present in the Electron packaged E2E chain.
- **Decision:** **reuse the existing Playwright verification layer, not its runtime code.** Keep the production semantic projection inside Fabushi, and use packaged Playwright evidence/contract tests to prove the exact state names and state transition.

### Candidate 3 — DOM Testing Library (`testing-library/dom-testing-library`)

- **Canonical repository:** https://github.com/testing-library/dom-testing-library
- **License / maintenance:** MIT; actively maintained.
- **Architecture / API:** a lightweight DOM-query layer whose core principle is testing the UI in the way users interact with it, with queries centered on DOM/accessibility semantics rather than component instances.
- **Test / operational edge cases:** it is valuable for user-facing role/name behavior, but accessible-name computation has standards/browser/DOM edge cases and its own issue history demonstrates that role/name resolution is not a substitute for a dedicated application automation identity/state contract.
- **Security posture:** appropriate for tests, but using a human-readable accessible label as the sole machine state would risk coupling automation to presentation copy and could tempt future exposure of sensitive peer/message text.
- **Fabushi compatibility:** useful as a testing philosophy, but it is a test utility rather than a production App Surface transport and would not solve remote `fabushi.app.find` state projection by itself.
- **Decision:** **learn from the user-semantic query principle but reject it as the runtime state mechanism.** Human peer/avatar text stays separate from the exact unread state contract.

### Resulting provenance / reuse decision

No surveyed project provides a drop-in replacement for Fabushi's existing `data-agent-id` + remote App Surface bridge. Pulling in a new UI/runtime dependency would widen the trusted surface for a two-state fix, while the existing protocol already has the required stable identity. The custom code is therefore necessary but deliberately small and follows the proven Radix finite-string state pattern: keep `peer-unread:<peer>` stable, expose only the two bounded state strings, and do not encode unread counts or message contents. Playwright remains the independent packaged verification layer.

No source code is copied from any candidate. No new third-party dependency is added. Consequently there is no new binary/source attribution obligation in Fabushi from this repair; the design references above are provenance/learning evidence only. Existing MIT/Apache-2.0 projects were inspected for architecture and test patterns, and no GPL/AGPL or otherwise incompatible implementation was adopted.

## Atomic repair

1. Keep the stable unread agent id `peer-unread:<peer>` unchanged.
2. Make the App Surface accessible/query name on this dedicated semantic node exactly `unread-none` or `unread-positive`; preserve the human peer/avatar label separately as `aria-description` rather than prefixing the semantic name.
3. Keep the controller's exact `agentId + name` lookup unchanged and fail-closed.
4. Extend the deterministic find contract so it rejects any human-label-prefixed unread semantic name and requires the exact semantic label plus preserved description.
5. Preserve all existing server-side redacted find selection, <=100 find limit, newest-message identity window, generation retry, exact-device/source, 27-category and logout/evidence gates.
