and received zero matches until timeout. The controller then wrote a FAIL note and called `ci_session_finish`; the target correctly rejected the run because the required `READY_FOR_LOGOUT PASS` note had never been emitted. Therefore FCM-010.13.11 and FCM-010.13 remain blocked.

## Root cause

The dedicated `peer-unread:*` semantic node is a chat-list avatar semantic. Fresh generated-regression snapshots prove the exact node exists while the chat list is rendered. The current `send` sequence calls `openAssistantConversation()` before verifying the false unread baseline; selecting the assistant conversation unmounts the list-only unread node. The subsequent exact `agentId + name=unread-none` lookup therefore cannot succeed even though the semantic projection itself is correct on the list surface.

## Open-source-first survey / reuse decision

This repair inherits and reuses the open-source survey already recorded by the immediately preceding FCM-010.13.11 semantic-name repair. That survey evaluated Radix Primitives (`radix-ui/primitives`, MIT), Microsoft Playwright (`microsoft/playwright`, Apache-2.0), and DOM Testing Library (`testing-library/dom-testing-library`, MIT) for deterministic UI-state exposure and semantic-query testing.

For this newly exposed blocker, the production semantic model is already correct; the defect is controller ordering across two real UI surfaces. No surveyed project provides or is needed as a replacement for Fabushi's production controller/App Surface transport. The relevant reusable upstream pattern is Playwright's stable semantic locator model, and Fabushi already carries Playwright in the packaged Electron E2E chain. The repair therefore **reuses the existing Playwright verification layer without adding or copying third-party runtime code** and keeps the production controller on Fabushi's existing `data-agent-id`/App Surface protocol. Radix's explicit finite-state design remains the provenance for the two-state unread semantic signal; DOM Testing Library remains useful philosophy but is not adopted as a runtime transport.

Security/licensing decision: no new dependency, source copy, binary, credential access, screenshot parsing, unread count, or message-text exposure is introduced. The exact bounded semantic name and production redaction remain unchanged. Existing MIT/Apache-2.0 upstream projects are referenced for architecture/testing patterns only, so this repair creates no new attribution or copyleft obligation.
