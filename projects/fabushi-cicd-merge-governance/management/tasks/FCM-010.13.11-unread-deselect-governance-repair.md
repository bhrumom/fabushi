## Root cause proven from canonical source

The failure is not an old stale-generation/list-remount/`find limit` issue.

`third_party/mahayana/mahayana-rs/mahayana-runtime/src/kernel_conversation.rs` implemented `KernelConversationProvider::list_conversations()` as `Conversation::mahayana_assistant()`. The canonical helper initializes `unread_count` to `0`, so the production provider had no state capable of emitting a positive unread count after an assistant reply. Desktop Messenger projects legacy peer unread directly from `conversation.unreadCount`; therefore the exact App Surface semantic marker could never become `unread-positive` on this provider.

A second projection gap existed at the renderer transport boundary: assistant `chat.message` completion updated the message journal but did not request a fresh authoritative `conversation.list`, so even a corrected runtime unread count would not necessarily reach the peer list immediately.
