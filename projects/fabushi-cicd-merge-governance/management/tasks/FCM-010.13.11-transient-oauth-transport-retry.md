The external controller did not reach the semantic journey. Its very first OAuth network operation failed with a transient TCP reset:

`TypeError: fetch failed`

with cause:

`Error: read ECONNRESET`

The controller exited immediately because OAuth bootstrap had no bounded transport retry. This is distinct from authentication rejection, schema failure, App Surface semantics, source binding or device ownership. Since the controller never obtained MCP authorization, it never began the 27-category journey and this run cannot be accepted.

## Open-source-first survey and standards decision

Survey performed on 2026-09-12 before choosing the retry policy.

### Candidate 1 — AWS SDK for JavaScript v3 (`aws/aws-sdk-js-v3`)

- **Canonical source:** https://github.com/aws/aws-sdk-js-v3
- **License / maintenance:** Apache-2.0; actively maintained.
- **Architecture / retry model:** the standard retry strategy uses a bounded `maxAttempts` budget, exponential backoff, and retries only errors classified as transient/retryable. The SDK documentation explicitly supports a custom wrapper when precise underlying error classification is required.
- **Current production guidance:** the 2026 retry update keeps a default maximum of three attempts and explicitly treats connection resets as transient, with shorter backoff than throttling failures.
- **Fabushi compatibility:** high at the policy level. The FCM controller already uses native Node `fetch`; importing the AWS SDK solely for retry would be disproportionate.
- **Decision:** **adapt the bounded transient-only retry policy, do not add the dependency or copy source.** Use three total attempts and short exponential delays while retaining explicit error-code classification.

### Candidate 2 — Google API Extensions for Node (`googleapis/gax-nodejs`)

- **Canonical source:** https://github.com/googleapis/gax-nodejs
- **License / maintenance:** Apache-2.0; actively maintained by Google APIs tooling.
- **Architecture / API:** generated clients expose retry settings/timeouts through call options and keep retry behavior at the RPC boundary rather than silently retrying arbitrary application semantics.
- **Fabushi compatibility:** useful as confirmation that retry belongs around the remote transport/bootstrap boundary, but adopting gax would introduce an unrelated RPC stack.
- **Decision:** **adapt the boundary principle only; reject as a runtime dependency.**

### OAuth 2.0 protocol constraint — RFC 6749

- **Canonical standard:** https://www.rfc-editor.org/rfc/rfc6749
- Authorization codes are short-lived and MUST NOT be used more than once. Therefore a transport failure around token exchange must not trigger blind replay of the same code.
- **Decision:** each retry attempt restarts a fresh OAuth transaction (new dynamic client registration, PKCE verifier/challenge, browser login completion and authorization code), rather than retrying an individual token exchange with the same code.

### Provenance / security / maintenance result

No third-party source code is copied and no new dependency is added. The implementation is a small Fabushi-owned helper with an explicit allowlist of transient network error codes (`ECONNRESET`, `ETIMEDOUT`, `EAI_AGAIN`, reachability/connectivity and Undici timeout/socket codes), three total attempts, 250ms/500ms bounded exponential delays, and deterministic regression tests. HTTP authentication/authorization errors and all application/semantic failures remain non-retryable and fail immediately. The retry wrapper is used only for OAuth bootstrap; once MCP authorization succeeds, the existing fail-closed 27-category journey is unchanged and is never automatically replayed.

## Atomic repair

1. Add a shared bounded transient-network retry helper with explicit error-code classification.
2. Split OAuth bootstrap into one complete `authorizeMcpOnce()` transaction and wrap the whole transaction in a maximum-three-attempt retry.
3. Emit `oauth-attempt` and `oauth-transient-retry` evidence with attempt number, classified error code and delay.
4. Keep HTTP/status/semantic errors non-retryable.
5. Restart the entire OAuth transaction for a transient failure so an authorization code is never reused.
6. Add deterministic tests proving two `ECONNRESET` failures recover on attempt 3, HTTP 401 fails after one attempt, and persistent transient failure stops exactly at attempt 3.
7. Preserve exact source/tag/device binding, find limit, generation retry, unread false->true gate, 27 categories, READY/logout ordering and truthful evidence gates unchanged.
