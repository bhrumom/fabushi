# 2026-09-11 ChatGPT 会话异常结束后的自动重发

- Project ID: `FAB-P0001`
- Project Key: `TFI`
- Intake: 用户截图与明确行为要求，2026-09-11 20:20 Asia/Shanghai
- Related implementation: `bhrumom/fabushi-chatgpt-auto-confirm-userscript`

## 用户原始要求（语义保真）

当目标会话已经没有输出最终回复、没有授权卡片，并且输入框旁的停止按钮已经消失时，应判定该会话异常结束；工作台需要新开会话并原样重发，而不是继续无限等待。

## 复现事实

截图中的目标 ChatGPT 会话停留在多条“已调用工具”之后，编辑器已恢复普通输入状态，停止按钮消失，页面上没有最终 assistant 回复或授权卡片。2.9.3 的快速异常判断只有在监督器实际观察到 `Stop -> no Stop` 转换时才设置 `endedAt`。多任务轮询、页面恢复或晚进入该会话时可能错过转换，使 15 秒恢复路径永远不启动，只剩 5 分钟兜底。

## 规范化需求

- `TFI-USR-AR-R01`: 对已绑定且已稳定加载的正确会话，无停止按钮、无授权卡、无最终回复的连续稳定状态必须启动短异常倒计时，即使监督器没有亲眼看到停止按钮消失。
- `TFI-USR-AR-R02`: 停止按钮存在、授权卡存在、有效最终回复存在、会话不属于当前任务或页面阻塞提示存在时不得误判。
- `TFI-USR-AR-R03`: 异常倒计时到期后复用既有有限重试路径：清除旧会话目标，进入新 Work/规划会话并原样重发；重试次数上限保持 4 次。
- `TFI-USR-AR-R04`: 回归必须覆盖“首轮观察时停止按钮已经消失”的晚观察场景和原有 `Stop -> no Stop` 场景。
- `TFI-USR-AR-R05`: 发布版本必须单调增加，绑定 canonical source SHA、CI、Release 和真实 ChatGPT 视觉/诊断证据。

## 非目标

- 不把仍在生成、等待授权、限流或安全验证的会话强制重发。
- 不提高重试上限，不允许无限重试。
- 不改变任务 prompt、会话 URL 归属或标签页互斥模型。
