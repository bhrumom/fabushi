# 2026-09-11 ChatGPT 连接中断刷新与任务侧栏分组

- Project ID: `FAB-P0001`
- Project Key: `TFI`
- Intake: 用户截图与明确行为要求，2026-09-11 Asia/Shanghai
- Related implementation: `bhrumom/fabushi-chatgpt-auto-confirm-userscript`

## 用户原始要求（语义保真）

当 ChatGPT 页面显示“连接已中断。正在等待完整回复。”时，油猴脚本必须识别该页面状态并刷新当前网页。恢复任务记录不应继续放在工作台顶部的临时横条，而应进入左侧任务列表；任务按浏览器标签页工作区分组，并在列表中直接显示每个任务的当前状态。

用户进一步明确：本轮只处理油猴脚本，与 Fabushi 应用本体无关。

## 规范化需求

- `TFI-USR-DS-R01`: 仅从 ChatGPT 页面级可见提示识别“连接已中断。正在等待完整回复。”，不得由任务对话内容或 Fabushi 自身状态文本触发。
- `TFI-USR-DS-R02`: 命中后保留任务、会话 URL 和发送归属，受控刷新当前会话；不得把刷新当作新派发或重复发送。
- `TFI-USR-DS-R03`: 刷新必须有限次且有冷却/耗尽状态，避免持续存在的提示导致刷新循环。
- `TFI-USR-DS-R04`: 左侧列表按当前标签页工作区和每个可恢复标签页工作区分组；移除顶部“恢复任务记录”横条入口。
- `TFI-USR-DS-R05`: 每条任务记录直接展示中文状态、轮次和当前运行指示；可恢复工作区在组内提供明确恢复动作。
- `TFI-USR-DS-R06`: 轻量回归覆盖提示正反例、有限刷新状态、分组、状态展示和既有恢复互斥。

## 非目标

- 不修改 Fabushi Electron、Web、Android 或 iOS 应用。
- 不把普通断网、限流、安全验证或任务正文中的相同文字一概视为该专用恢复信号。
- 不绕过标签页 Web Lock 互斥，不改变异常无最终回复的新会话重发上限。
