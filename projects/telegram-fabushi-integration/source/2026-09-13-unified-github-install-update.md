# 2026-09-13 — 全平台小程序/插件 GitHub 安装更新方式

## 用户原始要求

把全平台的小程序、插件，都变成和油猴脚本一样的一个安装更新方式：小程序与插件的代码内容放到 GitHub，从 GitHub 拉取、安装、更新；市场也按照油猴脚本市场的标准设计。

截图只作为产品形态参考，不构成额外指令。

## 规范化要求

1. 每个可执行小程序/插件都必须有稳定的 `pluginId`、版本号、GitHub 仓库和不可变 `sourceRef`（tag 或 commit）；版本内容发布后不可覆盖。
2. 市场负责审核、搜索、版本指针、权限与平台元数据，不托管或代理安装包字节。每个可安装版本必须给出 GitHub/发布者 HTTPS 地址、SHA-256、大小、格式、入口、运行时和支持平台。
3. 桌面、移动、Web、CLI、Chrome/用户脚本等表面使用同一套“发现 → 获取版本清单 → 下载 GitHub 发布物 → 校验 → 安装 → 检查更新 → 更新/回滚/卸载”合同；平台可以选择不同 artifact，但不能各自发明一套安装状态。
4. 更新判断以 `pluginId + version + artifactSha256` 为准；禁止静默降级。安装与更新采用 staging、完整性校验和 active 指针切换，失败时保留旧版本可回滚。
5. 市场体验对齐油猴脚本：一键安装、显示已安装/当前版本与最新版本、明确的“更新”动作、版本来源/变更信息和权限预览；搜索结果只展示当前平台真正可安装的版本。
6. Web/移动端不能把未经校验的远程 JavaScript 直接注入宿主页。远程包必须交给对应 Host/runtime 安装，Web hosted surface 只加载声明的 HTTPS 页面或受控运行时。

## 验收边界

本要求承接现有 TFI M8 Marketplace 与 `mahayana.external-release.v1`，不新建第二个市场协议；本轮先补齐共享发布/安装/更新状态和桌面、Chrome、Web 的用户入口，再由 CI 在 Electron、移动和 CLI 运行对应的 packaged/installer journeys。
