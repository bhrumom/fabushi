# 2026-09-11 ChatGPT 油猴工作台关闭标签页后的任务恢复

Project: `FAB-P0001 / TFI`
Task: `TFI-USERSCRIPT-RECOVERY-001`
Source: 用户截图与问题反馈，2026-09-11

## 原始问题

用户在 ChatGPT Web 的 Fabushi 任务工作台中新建任务，随后关闭该浏览器标签页并重新打开一个 ChatGPT 标签页。新标签页的任务列表为空，旧任务记录不可见，界面也没有明显、可直接使用的恢复入口，因此用户无法恢复此前任务。

截图显示运行中的脚本界面为 `ChatGPT 自动确认 · Fabushi 2.9.2` 的“任务工作台”，新标签页状态为“当前标签页工作区”，左侧仅有“＋ 新任务”，顶部没有可见的任务恢复操作。

## 持久化后的要求

- 关闭标签页不得删除或隐藏到不可发现的任务目标、消息记录、状态及已记录 ChatGPT 会话链接。
- 新开的空白 ChatGPT 标签页必须直接提示存在可恢复的旧工作区，并允许在当前标签页恢复，不得要求用户知道隐藏在设置中的入口。
- 已完成、已取消、已暂停和进行中的任务记录都必须可恢复查看；只有用户明确删除的记录才不可恢复。
- 旧标签页仍存活时不得接管；并发恢复必须互斥，不能让两个标签页同时监督或派发同一工作区。
- 当前标签页已经拥有任务时，不得覆盖；应改用新的专用标签页恢复旧工作区。
- 恢复后保留原手动暂停语义。关闭浏览器期间脚本无法继续后台监督的产品限制必须继续明确。

## 初步根因

2.9.2 已把完整任务数组保存在同源 `localStorage`，但用 `sessionStorage` 中的标签页身份和 `ownerTabId` 过滤任务列表。关闭原标签页后任务数据仍在，新的标签页身份却看不到旧记录。既有“设置 → 恢复其他工作区”入口隐藏较深，并默认再开一个标签页，未满足新标签页直接恢复的用户预期。
