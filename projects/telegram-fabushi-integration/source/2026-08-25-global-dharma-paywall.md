# 全球法布施本地转经轮付费门槛

- **来源日期**：2026-08-25
- **来源类型**：用户直接需求
- **归属项目**：FAB-P0001 / TFI

## 原始需求

> 我现在需要你实现telegram一样的支付系统，在全球法布施小程序中设置付费门槛，全球法布施小程序的本地转经纶功能需要付费才可以开启，月付30元，买断1080元，按照telegram的付费系统实现，后续其他小程序也可以接入付费系统，按照telegram的标准去实现这些，合并进去要做完整的E2E支付测试，测试通过后发布新版本

## 规范化解释

1. 付费能力必须落在通用 Fabushi Pay，而不是全球法布施专用的前端开关。
2. 受保护能力为 `local.prayer-wheel.start`，GUI、自然语言、MCP、CLI、本地 Rust runtime 均不可绕过。
3. 商品：
   - 月付：人民币 30 元，30 天订阅周期，自动续费由对应平台支付渠道负责；
   - 买断：人民币 1080 元，永久权益；
   - 服务端使用整数最小货币单位：`CNY 3000` 与 `CNY 108000`。
4. 小程序只提交 SKU、支付渠道和幂等键；价格、币种、开发者、权益能力、期限和渠道映射均由服务端可信目录解析。
5. 数字功能按平台规则走 Apple In-App Purchase、Google Play Billing 或合规 Web provider；支付成功由服务端验签/可信 webhook 确认后才授予权益。
6. 必须支持恢复购买、取消、失败、过期、续费、全额退款撤销、webhook 重放幂等与账本平衡。
7. 合并前完成单元、集成及可视化 E2E；合并后在 canonical `main` 上重跑并发布严格更新版本。
