- anti-abuse
- session revoke

E2EE 规划：
- 普通云同步会话：服务端加密存储 + TLS
- Secret Conversation：端到端加密
- 后续可逐步扩展群组 E2EE

E2EE 必须有：
- device key
- identity key
- prekey
- session key
- key rotation
- safety number/verification
- multi-device key management
- backup/recovery 策略

不要自行设计未经验证的密码学原语；使用成熟加密库和经过审计的协议组件。

============================================================
二十一、性能目标
============================================================

客户端：
- 冷启动优先本地数据
- 会话列表首次可交互目标 < 1 秒（在合理硬件与已登录缓存情况下）
- 新消息本地入 UI P50 < 50ms（收到事件后）
- 大会话通过虚拟列表稳定滚动
- 本地搜索增量索引
- Rust core 不阻塞 UI thread

网络：
- 单连接多会话复用
- 批量 ack
- 批量 read state
- presence 聚合
- delta sync
- 二进制协议

服务端：
- 所有写入操作幂等
- 可水平扩容
- 热点群/频道专门优化
- 大频道 fanout 策略分层
- 离线推送异步化
