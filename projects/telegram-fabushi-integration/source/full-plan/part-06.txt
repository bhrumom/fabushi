二十五、实施阶段与里程碑
============================================================

M0：现状清点与边界固定
目标：避免重复建设和继续混入旧通信代码。

任务：
- 审查现有 Fabushi 通信相关代码
- 列出 Telegram/Grok Bot/旧联系人/旧 Agent 相关实现
- 标记保留/重构/删除
- 确定 workspace 目录
- 确定协议 IDL
- 建立 feature matrix
- 建立迁移 ADR

验收：
- 有唯一通信架构文档
- 有唯一模块 owner/目录
- 新功能不得再落到旧通信栈

------------------------------------------------------------
M1：Rust Core 骨架
------------------------------------------------------------

任务：
- fabushi-protocol
- fabushi-storage
- fabushi-messaging
- fabushi-sync
- fabushi-client-sdk
- SQLite schema
- Conversation/Message/Participant 基础模型

验收：
- Rust 单测通过
- 可本地创建会话/消息
- Electron 能通过 bridge 获取本地会话列表

------------------------------------------------------------
M2：自建实时网络 + 1:1 文本消息
------------------------------------------------------------

任务：
- gateway
- auth session
- websocket connection
- heartbeat
- reconnect
- message send/ack
- server sequence
- delta sync
- delivery/read state

验收：
- 两个 Fabushi 账号互发消息
- 断网恢复后消息不丢
- 重试不重复
- 多端可同步

------------------------------------------------------------
M3：桌面聊天完整交互
------------------------------------------------------------

任务：
- 会话列表
- 消息虚拟列表
- 回复/编辑/删除/转发
- 草稿
- 置顶/静音
- 搜索
- unread
- typing
- reaction 基础

验收：
- 桌面端日常 IM 能力可完整使用
- Playwright 覆盖核心流程

------------------------------------------------------------
