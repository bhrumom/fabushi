============================================================
二十六、功能矩阵与完成定义
============================================================

每一个功能只能标记为以下状态：
- NOT_STARTED
- IN_PROGRESS
- IMPLEMENTED
- TESTED
- E2E_VERIFIED
- RELEASED

禁止仅因为“有代码”就标记完成。

一个功能达到 DONE 必须同时满足：
1. 代码已进入正式架构
2. Rust/服务端测试通过
3. UI 可使用
4. E2E 验证
5. 错误处理存在
6. 权限正确
7. 日志/监控可定位
8. 文档/协议已更新
9. 无依赖旧临时路径
10. 已合并 main 或进入明确发布分支

============================================================
二十八、迁移策略
============================================================

不允许“一次性全部重写然后切换”。采用 Strangler 方式逐步替换：

1. 先建立新 Rust Core
2. 新消息走新 Core
3. UI 通过统一 SDK 访问，不再直接访问旧模块
4. 用 feature flag 按会话/账号灰度
5. 新旧双写只在必要的迁移窗口使用，并有明确移除日期
6. 旧代码只允许修阻塞 bug，不再增加功能
7. 每完成一个域，删除对应旧实现
8. 最终移除兼容层

数据库迁移要求：
- versioned migration
- backward-safe
- crash-safe
- migration tests
- rollback/forward strategy
