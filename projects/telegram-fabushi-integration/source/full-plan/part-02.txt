============================================================
六、自研通信协议与网络层
============================================================

目标：构建 Fabushi 自己的高性能实时通信协议，不复用 Telegram 网络。

第一优先级：
- TLS 1.3
- WebSocket 作为稳定基础通道
- HTTP/2 或 HTTP/3 作为 API/下载通道
- QUIC 作为后续高性能实时通道
- protobuf/compact binary encoding
- 请求 ID / trace ID
- ack
- retry
- timeout
- reconnect
- exponential backoff
- heartbeat
- connection migration（后续）

客户端发送状态：
Draft -> Queued -> Sending -> ServerAccepted -> Delivered -> Read
                             -> Failed -> Retrying

必须解决：
- 重复发送
- 消息幂等
- 网络断开
- 乱序
- 多端竞争
- 编辑/删除竞争
- 同一消息多设备 ack
- 大量未读增量
- 断线重连后的 gap recovery

增量同步：
- 全局 SyncCursor + conversation cursor
- 每次客户端带 last cursor
- 服务端返回 delta events
- 发生 gap 时自动补洞
- cursor 失效时支持 snapshot + delta 恢复
