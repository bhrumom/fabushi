## Four-group contract

1. **Execution group**: fresh chat reads exactly one authoritative task file, its dependencies and linked source; changes only that atomic scope; writes code, focused tests, commit/PR and task/project record. It may not self-declare review/test/release success.
2. **Code review group**: starts only after commit/push. It reviews the real branch diff, task record and affected project docs against acceptance criteria. Result is `REVIEW-PASS` or `REVIEW-REJECTED` with executable defects.
3. **Test release group**: starts only after `REVIEW-PASS`. It uses GitHub Actions to build/publish a test artifact and performs complete simulated-user journeys. It must retain pass and fail video, step screenshots, Playwright/driver trace, report and logs under the task evidence index.
4. **Formal release group**: starts only after code review pass **and** architecture/video review pass. It requires protected merge to canonical `main`, exact-main packaged E2E, repository release gates and a tested artifact. Only then may a formal release be created.

No local build/test substitutes for GitHub Actions. No test artifact or formal version is considered released merely because a branch workflow passed.
