## 旧栈删除策略

M0 代码审计前不能凭文档猜测实际旧目录名称。审计后必须建立“保留/重构/删除”清单，并满足：

- 一个能力只有一个正式 owner/module；
- feature flag 必须有删除日期/删除任务；
- 新栈通过验收后禁止新代码继续进入旧栈；
- 删除时检查 build files、CI、依赖、测试夹具、文档和运行配置；
- 无 GitHub/CI 证据不得声称旧栈已退出。

## Userscript 2.9.2 → 2.9.3 compatibility（2026-09-11）

- Keep the existing `fabushi-workbench-v2` localStorage schema and `fabushi-workbench-tab-session-v1` identity key; no destructive migration or task rewrite is required.
- A new empty tab may adopt an orphaned owner ID only after non-blocking Web Lock acquisition succeeds. A live owner must fail closed.
- Preserve manual pause, selected task, conversation URLs and terminal task history. Existing non-empty tabs continue to recover into a dedicated tab.
- Rollback is reinstalling 2.9.2; because storage keys and task shape are unchanged, records remain readable, although the first-class in-place recovery affordance is lost.

## Userscript 2.9.3 → 2.9.4 compatibility（2026-09-11）

- No storage or task-schema migration is required; the change only corrects the transient abnormal-end observation clock.
- Existing URLs, tokens, retry counters and four-attempt maximum remain compatible.
- Rollback to 2.9.3 preserves all task records but restores the late-observation delay defect.

## Marketplace legacy → GitHub immutable migration（2026-09-13）

1. 新发布先生成 `mahayana.external-release.v1` + `fabushi.marketplace.install.v1`，sourceRef 固定到 GitHub commit，并在 CI 计算 artifact SHA-256/size；旧 metadata 只能作为待迁移输入。
2. backend/Worker 返回时补齐统一合同并按平台筛选；缺少 public GitHub commit、artifact 或校验字段的 executable release 不进入新的可安装路径。
3. Desktop/mobile/CLI/Chrome 切换到 Host/verified userscript path；Web 迁移旧的 ID 数组到 `fabushi.marketplace.installs.v2`，旧记录显示为 legacy/需要重新取得版本，不宣称已验证执行。
4. Host 保留既有 per-plugin 版本目录和 active pointer；升级前写入 `previous-active.json`，只允许显式 rollback 回退。不会为了迁移删除用户已安装版本或静默覆盖 active。
5. 固定 catalog 的历史 hash/size 不一致或 gzip/archive 损坏必须重新生成并提升版本后再发布；在校验修复前保持 release blocked。回滚以最后一个 digest/size 一致的 GitHub Release 为准。
