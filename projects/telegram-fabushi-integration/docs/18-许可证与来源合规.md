## 原则

“完整融合”意味着功能、交互范式和工程能力完整，不等于不加审查地复制第三方代码。

每个外部来源必须记录：
- Repository / package；
- 精确 commit/tag；
- License；
- 使用方式：依赖 / 修改 / clean-room reimplementation / 仅参考行为；
- 进入 Fabushi 的文件；
- attribution / notice 要求；
- 是否形成衍生作品；
- 审查结论。

## 重点来源类别

- Telegram 官方开源客户端；
- Unigram 等 Telegram 客户端；
- Grok Bot；
- WebRTC/加密/协议/数据库依赖；
- 图标、字体、动画、音效等资产。

## 合并门禁

以下情况不得直接合并：
- 无法确定来源；
- License 未确认；
- License 与计划分发方式不兼容；
- 商标/品牌资源被误当作代码复用；
- 专有构建产物被当作“源码”迁入；
- 需要 attribution 但未补 notice。

本项目文档不是法律意见。遇到许可证边界不清的第三方实现，应在进入正式发布前获得相应法律/合规审查。
