## 架构原则

A. Rust First
- 网络、协议、加密、消息状态机、本地存储、同步、媒体、搜索、队列使用 Rust。
- UI 不重复实现通信逻辑。
- Electron 通过 Node-API/IPC 调用 Rust Core。
- iOS 通过 UniFFI/Swift bindings 调用 Rust Core。
- Android 通过 UniFFI/JNI/Kotlin bindings 调用 Rust Core。

B. Protocol First
- 先定义协议与状态机，再写 UI。
- 所有客户端使用同一份 protobuf/serde schema 或等价 IDL。
- 协议版本化，支持向后兼容。

C. Local-First
- 本地数据库保存会话、消息、草稿、索引、媒体元数据。
- UI 首屏优先读取本地数据。
- 后台增量同步。
- 断网仍可查看历史消息、草稿和已缓存媒体。

D. Event Driven
- 服务端以事件日志和增量同步为基础。
- 客户端通过统一事件流更新状态。
- 避免 UI 直接耦合具体后端接口。

E. AI Native
- AI Agent 不是外挂聊天页面，而是通信网络一等公民。
- Agent 与联系人共享会话模型，但权限、运行环境和工具调用必须隔离。

F. Self Hosted
- 核心通信能力必须可部署在 Fabushi 自己的服务器/VPS/云环境。
- 不依赖 Telegram API、Telegram Bot API 或 Telegram MTProto 网络。

G. Secure by Default
- 传输加密、设备信任、密钥轮换、敏感权限、支付权限、Mini App 权限从第一阶段设计，而不是上线前补。

## 2026-09-05 — CI evidence identity addendum

For protected-main gates, the commit actually present in the runner worktree is part of the architecture contract; a green workflow/job associated with a PR is not sufficient by itself.

- `pull_request` exact-head acceptance validates the final product commit itself. The canonical child must explicitly checkout the event PR head and raw evidence must show actual worktree HEAD equals that product SHA before the authoritative script executes.
- `merge_group` acceptance validates the merge queue's current combined commit. The same child must instead checkout the current merge-group SHA and prove that actual worktree identity before executing the same script.
- These identities are intentionally different. Reusing the PR head during merge-group would bypass queue-context validation; accepting the default synthetic PR merge during the PR exact-head gate would bypass product-head validation.
- Version logic remains centralized in `.github/scripts/assert-native-electron-canonical.sh`; checkout identity selection is orchestration, not a second source of version truth.
- Required aggregate status remains fail-closed. A skipped/neutral/manual/rerun/historical/different-SHA result is not architecture acceptance evidence.

This addendum is governed by ADR-0014 and `TFI-M6-MAINSAFE-001-VERSION-EXACT-HEAD-CHECKOUT-001`; it does not alter product/Rust runtime architecture.
