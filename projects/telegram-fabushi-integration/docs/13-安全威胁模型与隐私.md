基础要求：
- TLS 1.3
- token rotation
- refresh token 保护
- device-bound session（可实现范围）
- 新设备验证
- rate limit
- anti replay
- CSRF/XSS/SSRF 防护（Web/Mini App）
- signed media URL
- permission check 全服务端执行

E2EE：
建议分层：

普通云会话：
- 传输加密
- 服务端持久化加密
- 服务端可执行同步/搜索等功能

Secret Conversation：
- 端到端加密
- 服务端只存密文
- 设备密钥
- key agreement
- key rotation
- 安全码/设备验证
- message expiry

不要为了“完全像 Telegram”而自行设计未审计密码协议。优先采用成熟、经过审查的密码构件与协议设计。

## 核心威胁（项目管理补充）

| 威胁 | 控制方向 |
|---|---|
| 重放/伪造客户端事件 | nonce/sequence、签名/认证、服务端幂等 |
| 被盗 refresh token | rotation、设备绑定、撤销 |
| Mini App 越权 | origin 沙箱、manifest、用户授权、服务端权限 |
| Agent 越权工具调用 | 能力白名单、敏感确认、审计、数据域隔离 |
| 媒体越权 | signed URL、ACL 与消息权限绑定 |
| 支付 webhook 重放/伪造 | provider 验签、事件幂等表、ledger 唯一约束 |
| 消息重复/乱序 | client/server sequence、idempotency、gap recovery |
| 服务端日志泄漏 | 结构化日志脱敏、禁止 token/密钥/正文敏感字段 |

安全敏感变更在合并前必须有对应负向测试。

## 2026-09-13 — GitHub-first Marketplace supply-chain controls

- 只接受 public `https://github.com/owner/repo`，拒绝凭据、端口、query、fragment、可变分支和非 GitHub executable artifact。
- release manifest 与 install contract 必须同时声明同一个 `pluginId/version`；`sourceRef` 为 40 位 commit，artifact 的 SHA-256 和 size 在 metadata 与 Host 下载后各校验一次。
- `marketplaceHostsPackage` 必须显式为 `false`。Marketplace 是 metadata/index，不是包字节代理；这样可以保留 GitHub provenance、审查和撤回边界。
- Chrome 用户脚本只有在用户明确点击安装/更新后取得 pinned raw GitHub 内容；扩展拒绝重定向、超大响应、摘要/大小不符及缺少 UserScript marker 的内容，且不执行任意远程脚本注入。
- 更新按版本单调规则执行；降级不静默发生；Rust Host 在切换 active 前保存上一指针，失败或回滚不覆盖旧版本。Web 只记录已选 release metadata，执行包仍需 Host。
- 未来接入签名时，签名应作为 digest 之外的附加验证，不得以市场自身转发包字节取代 GitHub provenance。日志不得记录 token、完整 artifact 内容或用户文件。

本轮安全/供应链验收结果：固定 catalog 的三项损坏或 hash/size 错配 archive 已由 CI 重建为 `1.0.1`，旧资产未原地覆盖；repair workflow `34769542406` 与 immutable package Release `marketplace-v1.0.1-cc23420c56c9` 可回溯到修复主线。最终 `desktop-1.2.65` 的 SHA256 manifests 通过自引用检查，Chrome package 也保留独立 checksum manifest。签名扩展、撤销服务和更广泛沙箱审计仍属于后续 M8 安全工作，不因本任务的 Release 被视为已完成。
