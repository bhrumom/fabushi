## Active M8 MiniApp MCP service-call acceptance — 2026-08-23

`M8-CALL-001` = `IN_PROGRESS`，PR #2063。用户最新要求已经固定为 MCP-only execution：

1. MiniApp 客服所有业务能力最终只能通过目标 MiniApp 的 MCP `tools/call` 执行；AI、DTMF、聊天输入和宿主代码不得存在平行业务 action executor。
2. DTMF 与聊天框纯数字必须走同一 `digits -> MCP Tool + arguments` route。
3. route 只能引用目标 MiniApp `tools/list` 实际暴露的 Tool；未暴露 Tool 不得成为有效 route。
4. final speech / chat natural-language 只能在当前 MiniApp Tool catalog 中解析；AI 只能选 catalog 内 Tool 并构造参数。
5. catalog 外 Tool 选择必须由 Rust domain 拒绝；无匹配 Tool 必须产生 `McpCapabilityUnavailable`，不得 fallback 到 Agent/native/其它 MiniApp。
6. 实际业务执行 effect 必须是 `InvokeMcpTool`；MCP result 再投影回统一 Conversation/Message。
7. write/destructive/open-world/sensitive Tool 必须继续沿用现有 MCP Apps 审批、授权和 sensitive-input 语义。

M8-CALL-001 只有在 latest-head Rustfmt、unit/contract tests、Clippy、required repository gates、protected merge、canonical-main readback 全部有证据后才能晋级 `TESTED`。`M8-CALL-002/003/004` 仍分别承担 STT/Conversation projection、真实 `tools/list` + constrained resolver + `tools/call` Host executor、composer routing，不能因 core contract 已写就宣称完整客服电话功能完成。
