## Observed failure

The iOS UI suite failed twice in `testHomeMatchesConversationLayoutAndMarketplaceRemainsReachable` at `FabushiUITests.swift:113`. XCTest attempted to tap the visible `返回` button while the projected accessibility element carried identifier `remote-computer-surface`; `XCUIElement.tap()` then failed its `AXScrollToVisibleAction` with `kAXErrorCannotComplete`. The same run completed the subsequent dedicated Mini App WebMCP return flow successfully, isolating the blocker to the remote-computer surface accessibility projection rather than general navigation or WebKit closure.

## Root cause boundary

`RemoteComputerSurface` assigns `remote-computer-close` to its `返回` Button but also assigns `remote-computer-surface` directly to the containing root `VStack` without first declaring that root as an accessibility container. SwiftUI can project the ancestor identifier onto descendants in that shape, so the test fallback resolved a Button whose identifier was the surface marker instead of the close control. The failure is deterministic in two repetitions of the same UI test.

## Atomic repair

Declare the root remote-computer surface as `.accessibilityElement(children: .contain)` immediately before its parent `.accessibilityIdentifier("remote-computer-surface")`. This preserves the parent surface marker while keeping child accessibility elements, including `remote-computer-close`, independently addressable. No remote-computer networking, WebKit policy, authentication, messaging, Windows code, release workflow, or test assertion is weakened.

Acceptance for this repair is the protected PR path plus GitHub Actions Native iOS simulated-user validation. After protected merge, Windows release testing must advance to a strictly newer global version from then-current canonical `main`; the failed `1.2.48` candidate is not releasable.
