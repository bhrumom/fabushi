# TFI-M11-ANDROID-INTERACTIVE-001 — Android 1.2.39 interactive checksum failure

- Immutable released APK: `android-v1.2.39-262490741` -> `6ea18f731759081a5e64d26ccb10d31d1f720ea6`.
- Release workflow: `34019773315`; release publication and automatic Android interactive dispatch both succeeded.
- Automatically dispatched interactive workflow: `34020127055`.
- Requested interactive identity was exact: `RELEASE_TAG=android-v1.2.39-262490741`, `RELEASE_SHA=6ea18f731759081a5e64d26ccb10d31d1f720ea6`, `DEVICE_ID=gha-34020127055-1-interactive`.
- The emulator cold-booted successfully and adb reached `sys.boot_completed=1`.
- The released APK checksum itself passed, but the script then failed `sha256sum -c SHA256SUMS.txt` because `fabushi-android-update.json` was listed by the immutable release checksum manifest but had not been downloaded into the verification directory.
- Failure happened before `adb install`, protected-account login, App launch, or App-owned gateway registration. Accordingly no Android device from run `34020127055` appeared in `fabushi test`; no historical device was substituted.
- Failure evidence was uploaded even on failure as Actions artifact `android-interactive-app-e2e-34020127055-1`, artifact ID `9985225969`, size `17,901,887` bytes, digest `sha256:c70c202c8bb692cb7e6fe2490ab2f2e715ba11710c05ff0de297b0e688df9fcf`.

## Atomic correction

The interactive runner must download `fabushi-android-update.json` from the same immutable release before running `sha256sum -c SHA256SUMS.txt`. The existing tag/SHA identity gate, APK download, checksum manifest, recording-before-install order, post-install login, App-owned registration, six semantic tools, real logout, and always-uploaded evidence remain unchanged. A narrow contract assertion locks the metadata download before checksum verification.

## Retest requirement

After protected merge, publish a strictly newer Android test release from the then-current canonical main and allow the release workflow to self-dispatch the interactive lane. Only the fresh `platform=android`, `metadata.kind=github-actions-android-app` device bound to that new run may be selected for external six-tool acceptance.
