# TFI-M11-ANDROID-INTERACTIVE-001 — Android 1.2.41 authenticated semantic surface unavailable

- Immutable release: `android-v1.2.41-262490800` -> `43a2946df2359d4949e510f344dfc7e4e67ee2a3`.
- Release workflow: `34020643552`; immutable release publication and automatic interactive dispatch succeeded.
- Interactive workflow: `34020990627`.
- Fresh App-owned device: `gha-34020990627-1-interactive`, `platform=android`, `status=online`, `metadata.kind=github-actions-android-app`.
- No KRIS, historical device, iOS/macOS device or runner-owned gateway was selected.

## Real external six-tool evidence

The fresh Android App-owned gateway registered successfully, but the authenticated semantic surface was empty:

- `fabushi.app.status {}` completed with `available=false`, `screen=unavailable`, `generation=0`.
- `fabushi.app.snapshot {maxElements:200, includeText:true}` completed repeatedly with `screen=unavailable`, `generation=0`, `elements=[]`.
- `fabushi.app.find {role:"application", limit:25}` completed with no matches.
- `fabushi.app.wait {screen:"home", state:"present", timeoutMs:30000}` completed with `passed=false` and `screen expected home, actual unavailable`.
- `fabushi.app.assert {screen:"home", state:"present"}` completed with the same deterministic failure.
- `fabushi.app.action {generation:0, agentId:"profile-avatar", action:"invoke"}` failed with `app_surface_element_not_found`.

The six tool names were therefore genuinely exercised, but the feature matrix did not pass and no success is claimed.

## Root cause

This exact defect was deliberately called out as a risk in the original Android App-owned gateway source review and was deferred until the first real external `status/snapshot` result. `MainActivity` routes the fully authenticated state (`onboardingStep >= 3 && authResolved && loggedIn`) to `GrokMobileShellAndroid`, while the existing Android `FabushiAppAgentSurface.publish(...)` lived only inside the legacy `FabushiScreen` branch. The registered App-owned gateway and the authenticated visible shell therefore referenced the same `FabushiAppAgentSurface` instance, but no authenticated composable ever published into it, leaving generation `0` and `screen=unavailable` by construction.

## Atomic correction

- Pass the existing Activity-owned `FabushiAppAgentSurface` into `GrokMobileShellAndroid`.
- Publish bounded authenticated Grok home/compose/create-Bot semantics from that shell, including stable actions for legacy entry, search, add menu and Bot entry.
- Pass the same surface into authenticated Bot chat and publish bounded close/draft/send-or-stop semantics there.
- Keep the existing gateway, protected-account bootstrap, six-tool protocol, sensitive-input restrictions, release workflow and runner ownership unchanged.
- Add a narrow Android contract assertion that the authenticated route owns and publishes the same App surface.

The current 1.2.41 interactive run remains a failure evidence run. After protected merge this correction requires a strictly newer Android release and a fresh run-bound App-owned device before any matrix result can be accepted.
