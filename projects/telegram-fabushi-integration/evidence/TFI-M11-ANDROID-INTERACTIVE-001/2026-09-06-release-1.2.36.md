## Release gate

Only the protected-main merge of this version candidate may be dispatched to `Native Android GitHub release`. The release workflow must validate exact-source `CI result` and `Native mobile result`, build/sign the APK only in GitHub Actions, publish `SHA256SUMS.txt` and update metadata, and target the exact canonical main SHA.

## Interactive acceptance gate

After the immutable Android release exists, `Android interactive app device E2E` must be dispatched with that exact tag/SHA. It must start whole-session recording and logcat before install, install the published APK without rebuilding it, authenticate the protected test account only after installation, and let the installed Android App self-register a new account-scoped device with `platform=android` and `metadata.kind=github-actions-android-app`.

External acceptance must select only that current-run App-owned device and make real calls to all six tools: `fabushi.app.status`, `snapshot`, `find`, `action`, `wait`, and `assert`. The journey must cover login/authenticated state, navigation, chat, search, Agent, media/file, settings, sync, and a real final logout. Any semantic/product failure stays failed, preserves video/screenshots/device trace/logcat/report, and receives an independent fix PR plus a strictly newer release candidate before retest.
