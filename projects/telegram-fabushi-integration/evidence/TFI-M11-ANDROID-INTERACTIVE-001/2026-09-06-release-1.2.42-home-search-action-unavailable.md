# Android 1.2.42 — full-Fabushi home search semantic action unavailable

- Release: `android-v1.2.42-262490839`
- Release source: `67dfcfc17aa4f66066314ce7a0d41eade202a6a3`
- Interactive run: `34022804599`
- Fresh App-owned device: `gha-34022804599-1-interactive`
- Device kind: `github-actions-android-app`; no KRIS, historical device, or runner-owned gateway was used.

The authenticated Grok shell fix was verified first: `fabushi.app.status` returned `available=true`, `screen=grok-home`, `generation=2`, and all six `fabushi.app.*` tools completed successful calls. Search on the Grok shell filtered bots correctly, and New message transitioned into the full Fabushi `home` surface.

On full Fabushi home, `fabushi.app.snapshot` generation 38 exposed `home-search-button` as `role=button`, `name=搜索对话`, `enabled=true`. Invoking that exact current-generation element returned the device error `app_surface_action_unavailable`. This is not a stale-generation error and not an external connector refusal.

Exact-source inspection found the semantic publisher emitted `home-search-button` without an action, while the real Compose `ConversationHome` button mutated local `showSearch/searchQuery` state. Because those states were owned below the App-agent publisher, the App-owned surface could neither invoke the search toggle nor expose/control its `home-search-field`.

Atomic correction: hoist only the full-home search visibility/query state to `FabushiScreen`, bind the semantic button to the same toggle, publish `home-search-field` while search is open with `setValue`, and pass the shared state/callbacks back into `ConversationHome`. No messaging, authentication, release, gateway, or unrelated UI behavior is changed.

The 1.2.42 run is intentionally not logged out after this deterministic functional failure so its existing always-upload path retains failure video, screenshots, trace, logcat, and report. Retest requires a strictly newer Android release and fresh run-bound App-owned device.
