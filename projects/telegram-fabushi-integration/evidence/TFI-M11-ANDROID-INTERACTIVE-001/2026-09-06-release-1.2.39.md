## Release and interactive acceptance

Only the protected-main merge of this version candidate may be manually dispatched to `Native Android GitHub release`. The release workflow must validate the exact canonical source gates, build/sign the APK only in GitHub Actions, publish the immutable APK/checksum/update metadata, and then self-dispatch `Android interactive app device E2E` with that exact release tag and source SHA.

The interactive run must start recording and logcat before installation, install the published APK without rebuilding it, authenticate only after install, and let that installed Android Fabushi App self-register a fresh `platform=android`, `metadata.kind=github-actions-android-app` device for the exact Actions run. KRIS, prior devices and runner-owned gateways remain invalid.

External acceptance must use only that fresh run-bound device and make real calls through all six semantic tools: `fabushi.app.status`, `fabushi.app.snapshot`, `fabushi.app.find`, `fabushi.app.action`, `fabushi.app.wait`, and `fabushi.app.assert`. The feature matrix must cover authenticated state, navigation, chat, search, Agent, media/file, settings, sync and a real final logout. Video, step screenshots, device-gateway trace, logcat, report, release/checksum identity and diagnostics must be retained on both pass and failure. Any real product defect receives its own fix PR and a strictly newer release before retest.
