## Release contract

The signed self-updating `Native Android GitHub release` is explicitly `RELEASE_TIER=test`. It must publish only from protected-main history after the exact-source `CI result` is green; it retains immutable tag/release, signing, checksum, APK manifest and source-SHA validation. Formal Google Play delivery remains separate and unchanged.

The workflow generates a monotonic Android APK `versionCode` in GitHub Actions and binds it into `android-v1.2.37-<versionCode>`, the APK manifest and update metadata. Canonical `androidVersionCode=29` and iOS build number `29` are not falsified to emulate that release identity.

## Interactive acceptance

After the immutable release is published, dispatch `Android interactive app device E2E` with the exact release tag and exact canonical SHA. Recording/logcat must start before install; the protected test account is authenticated only after install; the installed App itself must register a fresh device with `platform=android` and `metadata.kind=github-actions-android-app`.

Select only that current-run App-owned device. Real calls to `fabushi.app.status`, `snapshot`, `find`, `action`, `wait`, and `assert` must drive login/authenticated state, navigation, chat, search, Agent, media/file, settings, sync and final logout. Any failure remains failed, keeps video/screenshots/device trace/logcat/report, and triggers an independent fix PR plus a strictly newer release before retest.
