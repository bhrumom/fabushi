# 项目章程

## 问题

当前 `bhrumom/fabushi` 同时承载 Web、Electron Desktop、Android、iOS、微信小程序、浏览器
扩展、Backend、CLI、论坛、商城、Marketplace、共享 Rust Runtime、第三方源码和治理记录。
平台之间共享相对路径、工作区锁文件、发布 workflow 和 secrets 边界，导致任何小改动都
触发跨平台耦合，贡献者也必须克隆整个仓库。

## 目标

在不破坏现有发布入口的前提下，将每个受支持平台落到独立 GitHub 仓库，并将共享能力单独
版本化。拆分完成后，平台仓库可以独立 clone、CI、Release、权限治理和回滚；源仓库只保留
治理/迁移索引，不再混合所有平台产品源码。

## 利益相关者

- 产品与平台维护者：确认源码边界和版本节奏。
- Release/CI 维护者：迁移 workflow、签名和 updater 入口。
- Backend/CLI/运维维护者：确认 API、命令行发布、数据库迁移和 secrets 归属。
- 贡献者：切换 remote、开发说明和发布流程。

## 约束

- GitHub `main`、项目记录和实时 Actions 是工程事实来源。
- 不在本机构建、打包或运行重型测试；使用 GitHub-hosted CI。
- 迁移期间保留原仓库和可回滚 refs，不做未经验证的删除。

## 成功定义

每个目标仓库有独立的源码边界、默认分支、README、CODEOWNERS、CI 和版本发布证据；平台
之间不再通过源仓库相对路径编译；原仓库完成治理-only 收敛并保留迁移/回滚记录。
