# 发布、迁移与回滚

## 发布顺序

1. 先创建空目标仓库和 branch protection；不改变源仓库 Release。
2. 发布 Core 版本并固定平台与 CLI 依赖。
3. 按依赖顺序迁移 Core/Backend/Web/WeChat/Marketplace，再迁移 CLI/Desktop/Android/iOS/
   Browser，最后迁移 Forum/Commerce 的独立部署链路。
4. 每个平台先在新仓库生成 candidate Release，完成 packaged/E2E/安全证据后再切换生产入口。
5. 所有平台通过后，才把源仓库产品目录移入治理-only 过渡提交，并保留 archive tag。

## 回滚触发器

- 目标仓库缺少保留路径或提交历史映射不完整。
- 平台/CLI 构建、签名、E2E、部署、updater 或商店提交失败。
- secrets/个人数据/第三方受限资产被导出。
- 源仓库和目标仓库的生产版本无法对应。

## 回滚方法

停止当前平台切换，保留源仓库作为生产源；恢复旧 CI/部署引用；使用源 SHA 和 refs 清单
重新生成目标 repo。禁止通过删除 GitHub Release、强制覆盖不可逆 tag 或删除源目录来“修复”
迁移失败。
