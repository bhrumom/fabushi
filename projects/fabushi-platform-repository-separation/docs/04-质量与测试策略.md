# 质量与测试策略

## 本地限制

本机只允许读取、路径/依赖审计、manifest 校验、Git 元数据检查和文档审阅；禁止应用构建、
打包、原生/模拟器/E2E 或可能生成大型产物的测试。

## 目标仓库验证

每个目标 repo 至少需要：

- 轻量 lint/typecheck/contract check；
- 平台对应 unit/integration 测试；
- packaged/installable build；
- 关键模拟用户旅程；
- security/secret/license/path boundary scan；
- CI summary 记录 cache hit/miss、source SHA、目标 SHA、时间和 artifact。

Electron、Android、iOS 必须保留完整截图、视频、trace、平台报告和日志；Web/WeChat/Backend/
Forum/Commerce/Marketplace 至少保留构建日志、关键 smoke/E2E 和部署/Release 证据；CLI 还要
保留命令行 contract、help/version、安装/升级和 checksum 证据。

## 质量门

`Project portfolio governance` 先验证 PRS 注册。之后每个仓库使用自己的 required checks。
任何一个平台失败只阻塞该平台，不得把未验证的平台标记为 passed；全量拆分只有在所有目标
仓库达到其定义的门后才可关闭。
