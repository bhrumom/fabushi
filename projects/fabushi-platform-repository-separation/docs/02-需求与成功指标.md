# 需求与成功指标

| ID | 需求 | 成功指标 | 证据 |
| --- | --- | --- | --- |
| PRS-REQ-001 | 每个平台独立仓库 | 目标矩阵中的每个 repo 在 GitHub 存在且默认分支可读 | `gh repo view`、仓库 URL |
| PRS-REQ-002 | 平台边界不混合 | 路径审计显示平台仓库不含其他平台源码；共享代码只来自 Core 版本依赖 | old/new manifest、依赖审计 |
| PRS-REQ-003 | 历史可追溯 | 每个目标记录源 SHA、导出方式和目标 SHA；保留清单无意外缺失 | extraction manifest、tree diff |
| PRS-REQ-004 | 独立工程循环 | 每个目标 repo 有独立 CI、CODEOWNERS、README 和失败可回滚的 Release 流程 | Actions/branch rules |
| PRS-REQ-005 | 共享 Core 可版本化 | 平台不使用源仓库相对路径；Core 通过 release、registry 或只读 submodule 固定版本 | lockfile/commit pin |
| PRS-REQ-006 | CLI 独立交付 | CLI repo 可独立构建、发布 binary/container，并有自己的 version/Release | CLI Actions/Release |
| PRS-REQ-007 | 发布入口不回归 | updater、App Store/Play、Cloudflare、Chrome Web Store 和服务部署引用新的仓库/Release | CI/package/E2E evidence |
| PRS-REQ-008 | 原仓库安全收敛 | 只有在全量平台通过后才移除产品源码；迁移期间可按清单回滚 | main readback/rollback log |
| PRS-REQ-009 | 无密钥泄漏 | 新仓库和迁移日志不包含 secrets、cookie、签名材料或测试账户状态 | secret scan |
| PRS-REQ-010 | 低风险验证 | 重型导出/构建/E2E 均在 GitHub-hosted CI 完成，本机只做轻量审阅 | Actions runs |
| PRS-REQ-011 | 证据可重建 | 每个目标的源 SHA、目标 SHA、run、artifact、Release、时间戳均可回查 | `evidence/PRS-*` |
