# 19 完成定义与验收

## Implementation complete

某能力最多可在以下都成立时标记 `IMPLEMENTED`：来源/目标归属已记录；正式实现落在 Fabushi 模块；无已知重复主通道；provenance 决策存在；实现 commit/PR 可定位。

## Tested / E2E verified

`TESTED` 需要适用的 unit/contract/integration 通过证据；用户路径或高风险平台行为只有真实 E2E 通过后才可标记 `E2E_VERIFIED`。没有客观 evidence 不能人工升级。

## Release complete

`RELEASED` 需要受保护 main 合并、required CI、适用 artifact/release/deployment、post-release 验证和 rollback 路径证据。

## Migration complete

临时 compatibility layer 已退出或有明确仍需保留的版本契约；canonical model 唯一；历史 Grok 路径不再承担产品权威运行责任。

## Project complete — “所有功能所有源码已融合”

必须同时满足：

| Gate | Verification | Evidence |
|---|---|---|
| 来源覆盖 100% | M1 manifest + capability/diff matrix 无未分类关键项 | GBF-101..105 evidence |
| 正式模块归属 100% | 架构审计无第二套长期 runtime | GBF-301..306 evidence |
| 保留能力全部验证 | 所有 required WBS task 达到所需 TESTED/E2E_VERIFIED/RELEASED | acceptance matrix + CI |
| 高风险安全闭环 | allow/deny/revoke/expire/replay/recovery suites green | GBF-401..407,701..704 |
| 来源合规阻塞为 0 | provenance ledger blocking count = 0 | GBF-105/703 |
| main/release 事实一致 | GitHub main、CI、release/deployment 实时核验 | evidence index |
| 历史分支退出权威 | ADR 记录 archive/retain policy | GBF-804 |

在所有 gate 通过前，项目必须报告真实阶段和剩余任务，禁止把“源码在某个分支里”表述为项目完成。

## GBF-411 completion gate

GBF-411 is complete only after PR review/CI/protected merge; canonical-main Web/Electron/Android/iOS checks; exact-main packaged Electron App MCP interaction and evidence; the live Runner device showing both `fabushi.app.*` and the original `computer_*` tools; third-party native/browser semantic fallback proof; remote MCP deployment/readback; and the applicable exact-SHA Release/post-main records. Local Node tests alone are implementation evidence, not completion.
