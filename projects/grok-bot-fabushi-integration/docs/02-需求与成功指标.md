# 02 需求与成功指标

本标准文档归一化 `REQUIREMENTS.md` 与 `SUCCESS_METRICS.md`，原始用户要求保存在 `source/grok-bot融合优化.txt`，不得用本文件改写原始文本。

## 功能/工程需求

| ID | Requirement | Objective acceptance |
|---|---|---|
| GBR-001 | 完整盘点 Grok Bot 历史融合源码与功能 | 来源分支和 main 的关键文件/能力 100% 分类 |
| GBR-002 | Grok 独有且应保留的能力融合进 Fabushi 正式架构 | 每项保留能力有目标模块、实施 PR、自动化证据 |
| GBR-003 | 不保留第二套长期 Agent/Host/会话运行时 | 架构审计只剩一条正式 Agent/Tool/Host 控制链 |
| GBR-004 | Electron main/preload/IPC/host 安全收敛 | 最小 IPC contract、allow/deny、错误与权限测试通过 |
| GBR-005 | 电脑控制与本机执行可审计、可撤销 | grant/deny/revoke/expire/replay/recovery E2E 通过 |
| GBR-006 | 动态头像/动画成为 Fabushi 自研可维护模块 | 无生产 Grok runtime 依赖，有状态机、性能和 reduced-motion 证据 |
| GBR-007 | 所有迁移能力具有自动化验证 | 实施任务均有适用的 unit/contract/integration/E2E/CI 证据 |
| GBR-008 | 来源与许可证边界可审计 | provenance ledger 无未处理 blocking 项 |
| GBR-009 | 历史 Grok 分支不得整分支覆盖 main | 所有迁移以原子能力 PR 进入受保护 main |
| GBR-010 | 高风险变更可回滚 | feature/capability gate 或经验证回滚步骤存在 |
| GBR-011 | 对指定 Grok Bot 0.18 重构仓库实现完整可追溯覆盖 | 2,111 个固定 source-tree path 全部有能力域和复用/重写/拒绝决策 |
| GBR-012 | 新会话可选择 Fabushi、Codex、Claude Code 或 OpenRouter 推理提供方 | Router 设置、就绪诊断、持久化、流式回复和失败关闭路径通过 packaged E2E |
| GBR-013 | 路由后的会话继续使用同一 MCP/tool 权限与 transcript 语义 | 各提供方 tool call id、审批、富文本、恢复和 usage contract 通过 |
| GBR-014 | 用户可选 loopback-only 本地容器执行环境 | owned-container 身份、只读构件、端口绑定、重建/停止/非 owned 拒绝路径通过安全 E2E |

## 成功指标

- 来源能力分类覆盖率：100%。
- 关键能力正式模块归属率：100%。
- `IMPLEMENTED` 以上任务客观测试证据率：100%。
- `RELEASED` 任务要求的 E2E/CI/发布证据率：100%。
- 高风险 IPC/本机能力的允许/拒绝/撤销/过期路径覆盖率：100%。
- 未登记来源/许可的迁移代码：0。
- 整分支合并导致退役架构回流：0。
- 同一用户动作存在两套正式 Agent/Host 执行链：0。
- 指定 0.18 重构 source tree 未分类路径：0。
- Router 提供方绕过 Mahayana tool/capability policy 的路径：0。
- 未经所有权校验被 Fabushi 停止/删除的本地容器：0。

性能阈值必须在 M1/M2 测得真实基线后固化；在无数据时不编造 P95/P99。
