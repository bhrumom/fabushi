# 03 架构与实现策略

## 当前状态

历史 `grok-bot-latest-source-fusion` 已包含 Electron main/preload/host/native capability/native edge/offline ASR/桌面 E2E 等代码输入；当前 `main` 中若干同名文件已经继续演进。因此来源分支不能作为可直接回灌的产品快照。

## 目标状态

`Renderer/UI -> versioned preload contract -> Electron main authorization/lifecycle -> capability-gated host adapters -> Mahayana sovereign kernel/tool runtime`。

- Renderer：只负责界面/动画/交互，不执行任意 shell。
- Preload：只暴露最小、版本化、可测试 contract，不暴露通用 `ipcRenderer`。
- Electron main：窗口、系统生命周期、权限编排；不复制 Agent 核心业务。
- Host layer：文件/进程/浏览器/设备/电脑控制统一 capability gate。
- Mahayana：唯一正式 Agent loop、tool/MCP/extension、session/context/policy runtime。
- Platform adapters：隔离 macOS/Windows/Linux/iOS/Android 差异。

## 实施策略

每个 GBF 原子任务执行 `source/main diff -> 行为归类 -> 目标归属 -> 最小实现/重写 -> 自动化验证 -> PR -> protected main -> evidence`。禁止 wholesale branch merge。对来源许可不明确的实现采用功能行为规格 + 自主重写，而不是静默复制。

## 数据/兼容

长期只保留 Fabushi canonical model；若迁移需要临时兼容层，必须版本化、可删除且有退出条件。持久化变更必须有 forward migration、compatibility/rollback 限制与崩溃恢复策略。

长期决策见 `decisions/ADR-0001..0005`；深入模块映射见 `ARCHITECTURE.md` 与 `docs/03-目标架构与模块映射.md`。
