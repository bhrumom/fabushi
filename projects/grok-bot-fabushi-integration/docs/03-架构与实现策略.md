# 03 架构与实现策略

## 当前状态

历史 `grok-bot-latest-source-fusion` 已包含 Electron main/preload/host/native capability/native edge/offline ASR/桌面 E2E 等代码输入；当前 `main` 中若干同名文件已经继续演进。因此来源分支不能作为可直接回灌的产品快照。

## 目标状态

`Renderer/UI -> versioned preload contract -> Electron main authorization/lifecycle -> capability-gated host adapters -> Mahayana sovereign kernel/tool runtime`。

- Renderer：只负责界面/动画/交互，不执行任意 shell。
- Preload：只暴露最小、版本化、可测试 contract，不暴露通用 `ipcRenderer`。
- Electron main：窗口、系统生命周期、权限编排；不复制 Agent 核心业务。
- Host layer：文件/进程/浏览器/设备/电脑控制统一 capability gate。
- Mahayana：唯一正式 Agent loop、tool/MCP/extension、session/context/policy runtime。
- Platform adapters：隔离 macOS/Windows/Linux/iOS/Android 差异。

## 实施策略

每个 GBF 原子任务执行 `source/main diff -> 行为归类 -> 目标归属 -> 最小实现/重写 -> 自动化验证 -> PR -> protected main -> evidence`。禁止 wholesale branch merge。对来源许可不明确的实现采用功能行为规格 + 自主重写，而不是静默复制。

## 数据/兼容

长期只保留 Fabushi canonical model；若迁移需要临时兼容层，必须版本化、可删除且有退出条件。持久化变更必须有 forward migration、compatibility/rollback 限制与崩溃恢复策略。

长期决策见 `decisions/ADR-0001..0005`；深入模块映射见 `ARCHITECTURE.md` 与 `docs/03-目标架构与模块映射.md`。

## Provider Router vertical slice

`ProductHostSettings.inferenceProvider` is the persisted provider preference and `sandboxRuntime` is the persisted execution-environment preference. Electron reads the provider before each Host generation starts; Fabushi remains the default, while an explicitly selected and locally authenticated Codex session starts the existing in-process Codex compatibility backend through the same FeatureHost/Mahayana policy boundary. Provider changes restart only the Host generation; the renderer, transport contract, transcript DTOs, MCP path, approvals and usage events remain provider-neutral.

Readiness discovery is a native, read-only capability. It reports only booleans and source labels for local CLIs/session files or encrypted-vault entries. OpenRouter uses its official Chat Completions contract and Claude uses the official Messages contract; both normalize into the same Mahayana native engine event/tool/usage model. The legacy persisted ID `claude-code` is retained for compatibility, but a local Claude Code session is diagnostic only and is never treated as an Anthropic API key.

Provider switching preserves one product-owned assistant conversation. A bounded provider-neutral transcript is persisted below the runtime data directory and bootstraps a newly selected backend. Native providers additionally persist the exact native session snapshot so tool-call/result history survives Host generation recreation; a newer transcript invalidates a stale native snapshot after a Codex turn.

`local-docker` is an execution adapter below the existing Mahayana process capability/approval gate, not a second Agent runtime. Each approved process runs in a disposable, owner-labelled container with no network, read-only root, dropped capabilities, no-new-privileges, PID/memory/CPU limits, tmpfs `/tmp`, an active-workspace-only mount and a digest-pinned image. Host execution remains the default.

## Unified Agent Surface (GBF-411)

Fabushi uses one additive `fabushi.app.*` contract across WebMCP, Electron private App MCP, and native iOS/Android semantic state. The account-scoped remote MCP keeps dynamic device tool discovery: it forwards the schema published by the selected device rather than embedding a product-specific UI protocol. Control priority is App MCP -> browser DOM/accessibility -> native AX/UIA/AT-SPI -> bounded screenshot/coordinate fallback. The existing MiniApp WebMCP and full Computer Use registrar remain separate, authoritative capabilities.

Electron uses a loopback-only main/renderer bridge with a per-process bearer and 0600 discovery; it is not an arbitrary JavaScript or internal RPC endpoint. Mobile shells implement the same semantic model and platform-test adapters without bypassing platform background/account restrictions.
