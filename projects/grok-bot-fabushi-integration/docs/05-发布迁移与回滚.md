# 05 发布、迁移与回滚

## Rollout

- 运行时迁移按 GBF 原子任务进入受保护 `main`，不执行大爆炸 Grok 分支合并。
- 高风险能力默认 deny/off，通过 capability/feature gate 分阶段启用。
- desktop、native、Mahayana 各自受影响时运行对应 CI/E2E。

## Migration

来源能力先映射到 Fabushi canonical model；临时 compatibility adapter 必须标记 owner、删除条件和最后支持版本。数据 schema 变更需 forward migration 与读写兼容策略。

## Rollback triggers

权限绕过、敏感信息泄漏、数据损坏、严重崩溃/死循环、电脑控制目标漂移/不可撤销、关键回归均触发停用/回滚。

## Rollback steps

优先关闭 feature/capability gate；若需代码回滚，回滚最小任务 PR/commit，而不是恢复整个历史 Grok 分支。数据已发生不可逆外部副作用时必须显式说明限制，禁止宣称“完全回滚”。

## Ownership / validation

受影响模块 owner 执行回滚，release/CI owner 验证；post-release 验证必须重新运行关键 smoke/E2E 并记录 evidence。详细操作见 `runbooks/01-capability-rollback.md`。
