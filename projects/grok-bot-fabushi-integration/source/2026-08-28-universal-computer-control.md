# 2026-08-28 — 全平台账号绑定电脑发现、人工与 AI 远控

## 原始目标

从 Codex 会话 `01a04629-fda9-7e93-a6c2-0c42f9988b28` 延续实现：

1. Fabushi 桌面端安装并登录后，把本机注册为同账号可发现的电脑；关闭窗口后仍在后台保持 Host、设备心跳和必要的 WebRTC 信令。
2. 每个 Bot 资料栏提供“电脑”入口，展示设备在线/控制授权/配对/会话状态，并让远端控制请求可绑定目标 Bot。
3. Web、iOS、Android 能列出、配对并控制账号下电脑；人工输入和 Bot 自然语言任务共用同一受控执行边界。
4. 完整迁移现有 Computer Use 插件能力，包括应用/窗口发现、后台应用可访问状态、辅助功能树、语义元素操作、截图、坐标兜底、浏览器控制、短时引用和操作后重新读取验证。
5. 对 Grok Bot 0.18 reconstructed 的 VNC/noVNC 与 X11 模型控制路径做能力级比较；优先融合成熟开源架构，但不得引入第二套长期身份、会话、Agent 或权限权威。
6. 代码进入受保护 `main`，通过跨平台安全、打包和模拟用户 E2E，并从精确 main SHA 发布全平台可安装构件。

## 不可弱化的边界

- 设备在线/可发现不等于远程控制授权。
- 第一次控制必须配对；控制开关、客户端授权、会话 generation、device/session/client identity 必须同时匹配。
- 远控关闭立即终止活动会话，但保持同账号设备在线。
- AI 电脑操作仍受本机执行、AI 控制、工具审批、敏感输入、操作系统权限和人工接管约束。
- 移动端远控页面不得获得原生 JavaScript bridge；仅允许官方 HTTPS origin。
- 内置 Computer Use MCP 仅使用私有 stdio，不开放监听端口；策略文件缺失或不可读时必须 fail closed。
