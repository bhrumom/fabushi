# 07 安全隐私与合规

- Preserve fail-closed approval semantics for sensitive tools/capabilities.
- Secrets/auth storage must be Mahayana-owned at the product contract level; vendor implementations may exist only behind explicit adapters during migration.
- Never persist credentials/tokens in project records.
- Sandbox, filesystem, process, network, MCP, computer-control and MiniApp capabilities require explicit policy boundaries and auditability.
- Maintain Apache-2.0 attribution and third-party notices for reused/modified upstream code.
- `SOURCES.lock` and CI source-boundary checks are mandatory supply-chain/provenance controls.
- Any direct copied/ported implementation must retain legally required notice/history rather than being relabeled as original Mahayana code.
- ChatGPT project-team orchestration records may contain task metadata and
  evidence references only; they must never contain ChatGPT session cookies,
  access tokens, approval payloads, or other credential material.
