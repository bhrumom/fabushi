# 01 范围与非目标

## In scope
- Kernel/session/workspace/tool/memory/workflow/extension/model/policy domains.
- Codex sandbox/approval, app-server/session, MCP/connectors/skills/provider strengths.
- Grok Build worktrees/checkpoints, graph, prompt queue, goals/oracles, attempt journal, remembered approvals, loop protection, workflows/hooks/subagents, pause/resume/headless/ACP strengths.
- Fabushi differentiators: conversation-first actors, MiniApps, cross-device capability routing, shared host protocol, computer control integration.
- Source ownership/provenance checks and migration off direct vendor types.

## Out of scope
- Product rebranding without architectural independence.
- Copying entire upstream histories into canonical product crates.
- Reintroducing retired Flutter/Tauri app architecture.
- Hiding attribution or license obligations.

## Deferred until evidence exists
Exact claim of 100% upstream feature parity; deleting vendored Codex; removing all compatibility adapters.
