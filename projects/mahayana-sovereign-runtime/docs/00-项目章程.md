# 00 项目章程

## Problem
Mahayana historically inherited substantial Codex concepts/dependencies. A product that merely renames or bundles Codex/Grok code remains coupled to vendor identities and lifecycle assumptions.

## Objective
Own the product protocol, state machines, IDs, policy, workspace, tool bus, workflows, model routing and cross-platform ABI in Fabushi while selectively adapting/reimplementing upstream capabilities.

## Business/user value
One consistent agent runtime across Electron, native mobile, Web, CLI/headless and MiniApps; lower vendor lock-in; stronger long-running automation; faster independent product evolution.

## Constraints
- Current desktop architecture is Electron; mobile is native iOS/Android.
- Heavy builds/tests run in GitHub Actions, not locally.
- Apache-2.0 and third-party notices/provenance must be preserved for reused code.
- Existing working Fabushi features must remain compatible through staged migration.

## Success
Mahayana public contracts are vendor-neutral; upstream-specific code is isolated to adapters or removed; capability parity and differentiated behavior are proven with objective CI/E2E evidence.
