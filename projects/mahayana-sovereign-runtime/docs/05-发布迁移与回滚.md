# 05 发布迁移与回滚

Migration is capability-by-capability behind stable Mahayana contracts.

Sequence: native contract -> adapter/native implementation -> conformance tests -> surface integration -> default-path switch -> compatibility removal.

Rollback: retain previous adapter path behind a controlled compatibility boundary until the new native implementation passes the required release/E2E gates. Do not roll back the canonical Electron/native architecture by restoring retired Flutter/Tauri paths.

Release ownership follows Fabushi protected-main and existing platform workflows. Each stage records exact rollback triggers and evidence in its task record.

The project-team orchestration skill is released with the official plugin source.
Its contract validation is a prerequisite for the plugin package, but the skill
itself does not authorize bypassing product package, E2E, signing, or rollback
gates for application changes it coordinates.
